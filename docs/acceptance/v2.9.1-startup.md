# 2.9.1 startup acceptance boundaries

The candidate retains the Plan U implementation and historical evidence described
in [2.9.0 acceptance](v2.9.0-plan-u.md). Those approvals and native schema samples
are not approval or GREEN of this new commit.

The new narrow stage establishes two behavior-bound checks: literal complete
Codex composer identity through an owned native editor handoff, and immutable
startup ownership through a held initial-input failure. The coordinator keeps
RED/GREEN logs, source hashes, prototype identities, advisory snapshot and final
live receipts outside the product worktree.

The no-model terminal control probe distinguishes ordinary byte 0x07 delivery
from missing delivery with the same enhanced keyboard flags enabled by Codex.
A separate installed-Codex probe checks both independently selected buffers with
the child-local fallback. Neither probe sends Enter or submits a model request.

The expedited release profile requires a genuine Codex lifecycle on the clean
final commit: initial callback, same-session continuation, exact operation/resource
cleanup and no replay. Only Claude-dependent lifecycle/composition/Deep cells
are skipped under the user's explicit authorization. Full-suite/mutation/schema
reruns and approval-capable review are separately waived, not reported as PASS.

The final disposition must bind the exact candidate, disclose all omissions and
retain failed earlier probes. Missing live evidence leaves publication blocked.
No agent push, tag, PR, release or installed-plugin update is performed.
