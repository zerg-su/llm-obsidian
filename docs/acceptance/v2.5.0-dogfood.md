## Ten completed approved custom runtimes

The following command completed ten isolated full custom runs against the
release implementation: five `engineering/change` baselines and five
`engineering/fix` baselines.

```bash
for profile in change fix; do
  i=1
  while test $i -le 5; do
    CUSTOM_RUNTIME_PROFILE=$profile \
      python3 tests/harness/test_custom_runtime.py
    i=$((i+1))
  done
done
```

Every run independently:

- parsed and compiled a non-built-in-equivalent two-model-step spec;
- rendered and bound an exact explicit user approval;
- froze the definition hash in the existing owner store;
- accepted two typed child receipts;
- recovered typed result-without-submit through code-owned submission;
- ran the registered scoped verification profile;
- crossed an explicit review policy (`skip` in this transport-focused fixture);
- accepted one canonical Wiki Summary and reached finalization;
- left no duplicate callback or unresolved attention state.

The default `make test-harness` now runs both change and fix variants on every
release check. Separate compiler tests prove deterministic baseline selection,
built-in-equivalent rejection, exact approval, capability failure before
launch, bounded budgets, permission ceilings, and graph-bomb rejection.

## Dogfood repairs

The live window found six narrow harness defects, each fixed with a regression:

1. Codex runtime sync now fails before creating a task worktree.
2. Task prompts exclude `.task-*`, `.wiki-*`, and `.task-pipeline/**` transport
   from product commits.
3. Concurrent model and automatic callback publication no longer becomes
   false `callback-invalid` attention.
4. The task prompt renders the exact canonical Wiki Summary schema, including
   `schema_version`.
5. Cross-repository reviews submit through the trusted vault's transport
   script instead of assuming the product repository contains harness code.
6. Verification repair uses `pipeline-verification-resubmit.py` to derive the
   exact identity/hash response instead of asking the model to handcraft it.

The first failed Codex preflight left one recoverable, surface-free diagnostic
worktree at `/Users/zak/Projects/worktrees/df250-custom-codex-clamp`. It has no
live operation or process and is intentionally not deleted by release code.
The fix proves subsequent sync failure creates no worktree.

## Security and promotion exercise

The red-team compiler corpus rejected unknown fields/primitives, arbitrary
commands, provider-selected routes, unregistered checks, permission/effect
expansion, policy-only enforcement claims, unavailable capabilities, excessive
budgets, backward edges without bounded-loop control, traversal bombs, and
filesystem paths hidden in context pointers.

`test_custom_pipeline_report.py` exercised repeated normalized fingerprints and
confirmed that promotion reporting is content-free and never mutates the
registry. The two distinct live fingerprints each have one successful run, so
neither is honestly marked as a promotion candidate yet.

## Verdict

The 2.5 mechanism release gate is satisfied:
