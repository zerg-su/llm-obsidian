# 2.6.5 causal ledger: exact-HEAD review attempts

This ledger records root mechanisms, deterministic interleavings, and the
2.6.5 boundary that removes them. A timeout, retry, marker, screen change, or
resource disappearance is an observation; none is accepted as a root-cause
repair by itself.

| Defect | Deterministic fixture | Root classes | Causal interleaving | 2.6.5 boundary |
|---|---|---|---|---|
| D-264-73 | `tests/fixtures/v2.6.5/d264-73-terminal-parent-child.json` | R1 cross-HEAD continuity; R2 multiple writable truths; R5 session-preserving recovery | parent reaches callback-timeout attention → product HEAD changes → a resource-free verification child for iteration 1 is prepared against the retained parent | one ReviewAttempt freezes one HEAD and accepts only iteration 0; `changes-requested` is terminal, so no rearm, verification child, or provider continuation is legal |
| D-265 stale-exiting | `tests/fixtures/v2.6.5/stale-exiting-resource-gone.json` | R3 effect/liveness conflation; R8 resource-state divergence | schema-valid result exists → process disappears → workspace disappears → durable `resource-closed` is absent while child remains `exiting` and parent remains `awaiting-callback` | physical absence is not a positive transition; Subplan A preserves this causal fixture for the typed provider-event/resource reconciler owned by Subplan B |

## Root-class inventory

- R1: a mutable review gate allowed one provider session to span reviewed HEAD
  A and resolved HEAD B.
- R2: parent, verification child, gate context, current pointer, resolution
  evidence, and continuation receipt could disagree about the authoritative
  HEAD or terminal state.
- R3: transport activity and resource observations were used to infer business
  completion or safe replay.
- R5: recovery rearmed or resurrected a retained session instead of ending the
  old attempt and letting a bounded finalization cycle own a fresh attempt.
- R8: physical resource loss did not imply a durable close event, so state
  could remain `exiting` indefinitely.

## Removed new-path transition grounds

The exact-HEAD path does not use `awaiting_resolution`, continuation receipts,
same-session parent rearm, verification children, plan/current rebind, fresh
re-evaluation recovery, or checkpoint resurrection to cross a HEAD boundary.
Historical 2.6.x records remain available for inspect, archive, and resource
cleanup. Their resume disposition is the typed
`legacy-cross-head-resume-disabled`, with no provider effect.

Subplan A intentionally does not implement provider events or resource-close
reconciliation. The stale-`exiting` fixture is the causal input for that
separately owned work, not a claim that physical disappearance now proves
durable cleanup.

historical race classes to content-free declarations under
`tests/harness/lifecycle_scenarios/`. Each declaration names the independent
invariant that rejects the historical state before its current real-core path
is replayed.

They do not broaden a production transition or infer completion from virtual
time, physical disappearance, or a partial artifact.
