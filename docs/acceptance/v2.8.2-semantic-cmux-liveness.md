# v2.8.2 semantic cmux liveness acceptance

## Incident

Two mirrored 2.8.1 dogfood roots remained `awaiting-callback` while their
provider processes were alive. One exact workspace reported `Needs input`; the
other reported `Idle` with the Harness finalization prompt still visible in the
editor. The worker tracked only surface/process presence and full-screen hashes,
so dynamic status-line repaint continually refreshed `last_progress_at`.

The custom/fix notification seam also sent prompt text and `Enter` back to back.
cmux could accept both transport calls while the provider editor had not yet
materialized the paste, leaving a durable `sent` marker and visible unsubmitted
text.

## Accepted repair

- Strict exact-workspace semantic status decoding lives in the cmux adapter.
- `Idle` and `Needs input` suppress screen-repaint progress in the content-free
  liveness reducer.
- Retained notifications wait for exact editor visibility before one submit.
- An existing visible prompt may be submitted once through an fsync-backed,
  identity-bound recovery receipt; it is never re-pasted.
- Fresh paste and submit effects have durable write-ahead stages; uncertain
  stages never replay an external effect.
- Thread and process contenders serialize the complete recovery decision, and
  stale Codex collapsed-paste placeholders cannot authorize `Enter`.
- Historical prompt text cannot authorize `Enter`; recovery requires the
  matching notification to occupy the active provider composer.
- Claude recovery recognizes a current composer coalesced onto its horizontal
  separator, without accepting a transcript marker or provider dialog.
- Current review callback recovery re-reads lane checkpoint state after durable
  rehydration, so a concurrently restored checkpoint cannot strand an already
  accepted blocked callback or replay its reviewer effect.
- A durable frozen callback is consumed against its original attempt before a
  changed-HEAD successor is reserved, preventing immutable attempt-ID rebinding.
- Accepted callback bytes move to an immutable archive before successor launch.
  A direct predecessor-bound same-cycle lookup repairs the already-durable
  zero-effect outbox-failure prefix without replaying the reviewer.
- The accepted archive transition is durable before that launch: creation of
  `accepted/`, the destination rename, and removal from the source outbox are
  directory-fsynced in order. Interrupted rename and duplicate-cleanup prefixes
  re-establish both barriers on retry. The production recovery wrapper consumes
  the complete frozen multi-axis boundary even when an interrupted prefix has
  already removed one or every source outbox. Deterministic fsync and
  successor-start failpoints prove restart without reviewer replay. The exact
  mixed state (one archived axis plus one source outbox) and missing, extra,
  and non-string boundary-axis rejections are deterministic regressions.
- Session-preflight tests use per-run temporary fixture roots for every route
  snapshot. Concurrent runs leave the read-only product checkout unchanged.
