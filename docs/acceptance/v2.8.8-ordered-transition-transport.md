# v2.8.8 ordered transition transport acceptance

## Scope

This patch stabilizes the existing 2.8.7 Harness state machine against the
current cmux input transport. It adds no provider route, model call, pipeline
primitive, dependency, permission, or external publication effect. The
task-centric two-workspace topology from 2.8.6 is unchanged.

## Invariants

- Every Harness message written into a Claude or Codex editor targets one exact
  surface UUID and uses `terminal.paste` when cmux advertises
  `terminal.input.ordered.v1`.
- The adapter validates that cmux reports the same exact surface and an accepted
  paste. Missing capability falls back to the historical exact-surface send;
  malformed capability or RPC responses fail closed.
- Paste and `Enter` remain separate write-ahead stages. An unchanged idle frame
  after paste is observed through the bounded visibility window rather than
  being treated as an immediate delivery failure.
- Re-publishing byte-identical canonical callback outbox bytes is a successful
  no-op. A symlink, non-regular file, different identity, or different bytes is
  still rejected and never overwritten.
- Coordinator escalation and resolution messages use the same ordered editor
  transport before their single `Enter`.

## Evidence

- A live disposable Claude Sonnet Low prototype reproduced the legacy failure:
  the prompt remained idle with zero submits after `cmux send` plus `Enter`.
- The exact `terminal.paste` probe completed ten consecutive retained-session
  deliveries with ten `input-ready` observations and no lost input. The
  production adapter then completed one real initial Claude turn with one
  accepted submit and provider activity.
- `tests/harness/test_transition_transport_stress.py` drives nine registered
  production corridors for 50 repetitions each. It permits no duplicate
  callback, repeated prompt, extra `Enter`, or provider replay.
- `tests/test_pipeline_step_submit.py` races 50 identical submitters and
  requires every process to converge on the same immutable outbox bytes;
  foreign bytes remain unchanged and rejected.
- The complete Harness, model-routing, and repository gates are release
  requirements. Mirrored built-in and custom dogfood runs remain the
  post-install release acceptance.
