# LLM Obsidian 2.6.2 release-readiness ledger

Date: 2026-08-03

This is the bounded evidence entry point for the final 2.6.2 review. The
review packet, not this document, binds the exact final Git HEAD; the ledger
does not attempt an impossible self-reference to the commit that contains it.

## Model-free release gates

This tracked ledger intentionally does not claim that its own containing commit
is the final release SHA. The authoritative final verification packet includes
a content-free machine receipt named
`.vault-meta/release-evidence/v2.6.2-<short-head>.json`; the receipt itself
records and checks the full 40-character Git HEAD, each command, and each exit
code. The receipt directory is gitignored runtime evidence, so reviewers
receive its exact bytes and SHA-256 through the owner-only review packet rather
than through the checkout. A local `v2.6.2-final.json`, when present, is only a
superseded staging snapshot and is never release authority. The recorded
sequence is:

```bash
make test
make acceptance-check
python3 scripts/validate-vault.py --summary
python3 scripts/codex-adapter.py --check
scripts/mcp-gateway/mcp-gateway.sh codex-sync --check
git diff --check
```

The final receipt is generated only after the candidate HEAD is frozen. Any
later product or documentation commit invalidates that receipt and requires a
new exact-HEAD gate run. A read-only reviewer can inspect the receipt and
independently reproduce the full suite by checking its bound HEAD out into
owned writable scratch and running the same commands there.

## Bounded live cmux transition

The authoritative final receipt records both legs against its bound HEAD and
one exact workspace: first while a real harness-owned program is nonterminal,
then after that exact program has closed through the harness. The smoke never
inserts a synthetic `OperationRecord` merely to influence the projection.

The active assertion requires a non-empty truthful rendering and a successful
workspace-scoped publication. The terminal assertion requires `rendered=''`
and a successful publication, which invokes workspace-scoped
`clear-progress`. The receipt carries the sanitized command-evidence records
for both assertions; the committed content-free cmux tree fixture pins the
observed `windows → workspaces → panes → surfaces` hierarchy without titles,
paths, commands, or model content. Historical attention records with missing
exact surfaces do not contribute to either projection, and status collection
or publication never mutates operation state.
