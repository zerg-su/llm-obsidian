denominator without lowered floors, Git is clean before runtime-only evidence,
and status/doctor report no unknown or owned live resource. Local generated MCP
configuration may be initialized through the documented `sync-config --apply`
path; it remains ignored and does not change the candidate HEAD.

## Live and provider-availability boundary

The one allowed live dogfood uses the explicit Split activation facade, one
child, one Codex/Sol route, workspace placement and the existing
dispatch/session/cmux lifecycle. It records the exact manifest, launch receipt,
approved resource-free terminal receipt, current child HEAD and deterministic
join result. The harness, not this document, owns model invocation and cleanup.

The second provider is not probed. Its fallback decision is accepted only as a
typed freshness-bounded `AvailabilityEvidence` record from the registered
adapter/capability source. `unknown`, `unavailable` or stale evidence remains a
visible disposition and performs no fallback model call.

## Release boundary

Passing this checklist establishes readiness and the task outcome. Push, tag,
publish, install, deploy and release remain separately authorized actions and
are not performed by the 2.6.5 Join.
