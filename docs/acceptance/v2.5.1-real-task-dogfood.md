# LLM Obsidian v2.5.1 real-task dogfood report

Date: 2026-08-01

This report closes the real-task stabilization window that followed v2.5.0.
The original plan named ten tasks. During the window, the user explicitly
accepted nine completed tasks as sufficient for the 2.5.1 release gate and
moved RT10 to post-release dogfood after reinstalling the 2.5.1 adapters. The
accepted release mix is five Codex/Sol tasks, four Claude/Opus tasks, seven
simple reviews, and two deep reviews.

## Product findings

- The same-session delta prototype retained reviewer context and supported a
  machine-built bounded verification packet; no second reviewer session was
  needed.
- The vault audit found no actionable orphan set or genuine dead-link backlog,
  but repaired high-value navigation/index gaps.
- The pinned Superpowers/Matt Pocock comparison produced an explicit
  adopt/adapt/reject ledger without importing repository-specific issue, PR,
  worktree, or installer mechanics.

## Harness defects and repairs

- Terminal legacy operations could be misclassified as active; exact
  resource-free identity proof now distinguishes stale state.
- Abnormal acceptance exits could retain exact cmux surfaces; ownership is
  bound before provider start and cleanup is covered for exit, timeout, and
  interruption.
- Review callback evidence and final summaries had schema/order gaps; callback
  validity, prior-phase binding, bounded summaries, and finalization order are
  now explicit and regression-tested.
- Reap accepted ambiguous modes and could drop shared plans; modes now fail
  closed and shared plans remain durable.
- Runtime telemetry could overstate absence of Codex skill use; verdicts now
  state their observed-runtime boundary.
- Protected research had three layered launch failures: nonzero exits waited
  forever, interpreter resolution was not durable, and the isolated worker
  selected a cmux wrapper incompatible with sanitized `PATH`. Version 2.5.1
  classifies provider death immediately, pins the interpreter, and bypasses the
  wrapper only for protected fetch/synthesis.

## Replacements and scope decisions

No failed task was counted as useful and no duplicate replacement was silently
substituted. RT10 was not attempted or represented as complete. The user
explicitly shortened the release window after RT09: RT10 (`distill-runbook`)
will run after 2.5.1 is installed, as dogfood of the released adapter rather
than a prerequisite for stabilizing it.

## Model and runtime behavior

- Five tasks ran on Codex/Sol and four on Claude/Opus 5.
- Two engineering fixes used deep task review; seven tasks used simple review.
- The final release candidate is reviewed independently by Fable/spec and Sol
  xhigh standards/correctness/architecture/security lanes.
- Typed callbacks and durable receipts recovered several model omissions
  without replaying accepted phases; mechanism failures remained visible
  instead of being reclassified as product results.

## Human interventions

- The coordinator classified repeated managed-sandbox Unix-socket denials and
  performed host-side verification where the exact test required AF_UNIX.
- The user authorized pinned-only RT08 delivery after three distinct protected
  research launcher failures and later requested the complete launcher repair
  for 2.5.1.
- The user accepted the nine-task window and RT10 deferral before final release
  review; push, tag, and GitHub release remain manual user actions.

## Remaining material decisions

- RT08 did not verify live upstream drift. Re-run the protected comparison after
  2.5.1 installation if current upstream state is needed.
- Run RT10 after adapter reinstall and new-session skill reload.
- The Claude reviewer still lacks a convenient narrow read-only Git probe
  profile. The user moved that UX improvement to the 2.5.2 plan; it is not a
  2.5.1 behavior change.

## Gate evidence and verdict

At the release candidate HEAD, `make test`, `make acceptance-check`, vault
validation, Codex adapter sync, MCP config sync, upstream snapshot verification,
and `git diff --check` passed. Release remains blocked until the same Fable +
Sol deep review that requested this report approves the amended exact HEAD.
