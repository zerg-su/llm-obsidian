# RC2 vault-repair prototype

- **Question:** Can the existing transaction recovery, deterministic repair,
  validation, and scoped Stop commit be composed into the manual repair path,
  without a new executable façade?
- **Experiment:** Before product edits, ran
  `./scripts/with-timeout 55 bash tests/test_stop_hook.sh` against its disposable
  Git/vault fixture.
- **Decision:** Yes. Reuse `vault-write.py --recover`, `validate-vault.py
  --summary`, and the existing `.claude/hooks/stop.sh` owner. Add only a skill
  and a blocked-state handoff.
- **Limits:** The prototype covers local deterministic failures and preserves
  unrelated staged/dirty work. Ambiguous content, credentials, dependencies,
  provider transports, and coordinator/task ownership changes remain outside
  automatic repair.
- **Production follow-up:** Add `skills/vault-repair/`, emit the exact Codex and
  Claude invocation plus `.vault-meta/stop-hook-last.log` on blocked Stop, and
  freeze both behaviors in the existing instruction and Stop suites.

Prototype result: 67 passed, 0 failed on 2026-08-07.
