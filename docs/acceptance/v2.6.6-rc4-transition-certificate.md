# v2.6.6 RC4 — lifecycle transition certificate

Evidence carriers: `RC4-E5-transition-completeness`,

## What this certifies

The RC4 transition denominator is read from production, not from a test
expectation. `config/lifecycle-transition-v1.json` declares the state and
entry-point event vocabulary, every supported edge with one classification, a
curated forbidden-edge list, and one scenario set per named lifecycle case.
`scripts/lifecycle_transition_certificate.py` compiles that manifest against
every production owner in `denominator_source` — the state machine, the
operation contracts, the callback broker, the provider-event contract, and the
review contract — and reports, for one exact HEAD:

* missing supported edges — production edges the manifest fails to declare;
* extra supported edges — declared edges production does not implement;
* unclassified supported edges — declared edges outside the closed class set;
* unvisited supported edges — declared edges no scenario actually consumes
  through the production reducer;
* accepted forbidden edges — both for the curated list and for the closure over
  the whole state product.

A certificate is only `complete` when all five lists are empty, every declared
forbidden edge is rejected, and every named case carries a passing production
witness. `--check` refuses anything weaker.

## Case witnesses

Each named case drives a bounded production entry point rather than restating an
expectation. No case starts a provider, opens a surface, or performs any other
external effect.

| Case | Production witness | Path |
| --- | --- | --- |
| approval | approved review routes to `finalizing` | `CallbackBroker._next_state` |
| changes-requested | changes-requested review routes to `verifying` | `CallbackBroker._next_state` |
| fix-loop | blocked review raises attention, resume returns to the exact source state | `CallbackBroker._next_state`, `harness.state_machine.transition` |
| finalization | a summary is stable only after two identical reads | `RuntimeWorkerSummaryMixin.summary_is_stable` |
| summary-disposition | summary disposition, evidence, and gap pointers must agree | `wiki_summary_contract.validate_summary` |
| release-boundary | a missing digest, a byte substitution, a symlink escape, a parent traversal, and an absolute pointer are each refused | `rc3_release_disposition._bytes`, `rc3_release_disposition._matches_boundary_pointer` |
| callback-order | one callback wins, its replay is a duplicate, a rival is refused | `CallbackBroker.accept`, `OperationStore.accept_callback` |
| crash-point | a crash before the durable publish leaves an untorn prefix and resumes | `OperationStore.transition`, `OperationStore._observe_durable_boundary` |
| cleanup | the exact owned surface is closed exactly once, then converges | `harness.reconciliation.reconcile`, `harness.reconciliation.decide` |

## Excluded transport

`research` is the only explicitly excluded callback transport. The manifest
declares it in `excluded_transports`, the certificate rejects any other
exclusion claim, and `research` still appears in the production callback-kind
vocabulary so the exclusion stays visible rather than silent.

## Non-vacuity

`tests/harness/test_rc4_transition_certificate.py` mutates the manifest and
requires the certificate to go red each time:

* dropping a declared edge → `edges.missing`;
* inventing an unsupported edge → `edges.extra`;
* corrupting a classification → `edges.unclassified`;
* deleting the only covering scenario → `edges.unvisited`;
* **editing the config and its scenarios together** → still `edges.missing`,
  because the denominator comes from production, not from the manifest;
* declaring a legal edge forbidden → `forbidden.accepted`;
* dropping or inventing an event → `events.missing` / `events.extra`;
* an off-schema or non-`complete` certificate, an unknown witness, a repeated
  edge, an extra excluded transport, or a drifted denominator source → refused.

The suite additionally re-runs the independent simulator oracle over a real
crash-and-cleanup world and confirms it still catches a leaked terminal resource
(`SIM-INV-RESOURCE-FREE`) and terminal resurrection
(`SIM-INV-TERMINAL-MONOTONIC`).
