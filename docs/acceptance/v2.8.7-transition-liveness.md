# v2.8.7 transition liveness acceptance

## Scope

This patch stabilizes the existing Harness transition owners. Production
behavior adds no new provider route, model call, permission, dependency,
pipeline primitive, or external effect. The explicitly invoked acceptance
probe is different: it creates two isolated cmux workspaces, sends a bounded
number of provider-free editor messages and `Enter` keys, and closes those
exact workspaces. Cleanup failure is a gate failure, never a successful result.

## Invariants

- A valid callback may supersede an unsubmitted retained notification only
  when its registered operation and run identities match exactly.
- Supersession is durable and emits no `Enter`; an ordinary notification emits
  exactly one `Enter` after exact editor visibility.
- A long notification whose bounded visibility anchor ends on whitespace is
  compared after the same normalization as the rendered editor, so it cannot
  remain stranded at `transport-accepted` solely because of truncation.
- Claude initial input accepts the exact post-send `›` composer only when the
  final contiguous editor block contains the prompt anchor, or when Claude
  rendered its native collapsed-paste token. An earlier scrollback anchor, a
  bare `›`, and unrelated choices remain non-authoritative and cannot trigger
  `Enter`.
- Safely incomplete delivery remains pending. Uncertain write-ahead stages
  remain fail-closed.
- One exact operation revision and typed-result digest receives at most one
  model-free reconciliation. A changed revision or result receives a fresh
  stable-read window; unchanged state continues into bounded idle recovery.
- Concurrent task setup serializes the repository-common
  `extensions.worktreeConfig` mutation before any provider launch. The lock
  does not cover or merge the independent worktree-local exclude/config state.

## Deterministic evidence

`tests/harness/test_transition_transport_stress.py` executes 50 repetitions of
each registered corridor through its production owner: `run_dispatch`, the
built-in liveness reducer, the custom and engineering/fix worker mixins, the
bounded verification-attempt authority, the summary-refresh review bridge,
`CallbackBroker`, and `run_reap`. Both Codex and Claude editor shapes are
included. The test permits no duplicate callback, repeated prompt, extra
`Enter`, or provider replay. Its ninth corridor reproduces the Claude
initial-input handoff for 50 wrapped, collapsed, bare-composer, and matching-
scrollback-with-unrelated-composer cases.

`tests/test_dispatch_runner.py` also holds the first shared Git-config writer
until a second concurrent task worktree has attempted the same controlled lock.
It requires the second writer to remain excluded until release and verifies
that both independent `task-exclude` files contain the complete root-exact
transport set.

Focused continuation, liveness, custom runtime, and complete task-summary
tests cover the production consumers. `prototypes/v287_transition_liveness.py`
records the bounded provider-free question, evidence, decision, limitation,
and exact Git provenance. A separate real-cmux gate remains required before
promotion; `prototypes/v287_real_cmux_delivery.py` provides that bounded,
provider-free editor gate for both supported runtimes.

Run the hermetic ownership checks before the external gate, then publish one
immutable exact-HEAD receipt outside the product checkout:

```bash
python3 tests/harness/test_v287_real_cmux_delivery.py
python3 prototypes/v287_real_cmux_delivery.py --turns 20 \
  --receipt /private/tmp/v287-real-cmux/receipt.json
```

The receipt binds the exact Git HEAD and probe digest, the canonical creating
command (including its `--receipt` target), working directory, and Python
version, plus 20 accepted deliveries per runtime, zero provider/model calls,
and zero owned workspace tails. The gate samples both HEAD and probe bytes
before creating a workspace and again after cleanup; either kind of drift
fails without publishing a complete receipt. Exact creation references remain
available for cleanup even when structured workspace discovery is delayed,
malformed, or ambiguous; concurrent probes are checked only against their own
unique title and reference.
