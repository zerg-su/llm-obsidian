# v2.8.7 transition liveness acceptance

## Scope

This patch stabilizes the existing Harness transition owners. It adds no new
provider route, model call, permission, dependency, pipeline primitive, or
external effect.

## Invariants

- A valid callback may supersede an unsubmitted retained notification only
  when its registered operation and run identities match exactly.
- Supersession is durable and emits no `Enter`; an ordinary notification emits
  exactly one `Enter` after exact editor visibility.
- Safely incomplete delivery remains pending. Uncertain write-ahead stages
  remain fail-closed.
- One exact operation revision and typed-result digest receives at most one
  model-free reconciliation. A changed revision or result receives a fresh
  stable-read window; unchanged state continues into bounded idle recovery.

## Deterministic evidence

`tests/harness/test_transition_transport_stress.py` executes 50 repetitions of
each registered corridor: dispatch, built-in summary, custom step,
engineering/fix, verification retry, summary refresh, review callback, and
reap. Both Codex and Claude editor shapes are included. The test permits no
duplicate callback, repeated prompt, extra `Enter`, or provider replay.

Focused continuation, liveness, custom runtime, and complete task-summary
tests cover the production consumers. `prototypes/v287_transition_liveness.py`
records the bounded provider-free question, evidence, decision, limitation,
and exact Git provenance. A separate real-cmux gate remains required before
promotion.
