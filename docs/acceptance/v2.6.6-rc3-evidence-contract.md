# v2.6.6 RC3 executable evidence contract

RC3 keeps runtime capability unchanged and adds code-owned release evidence.
The following mapping is canonical; readiness and release notes link here
instead of duplicating counter or schema rules.

| Evidence | Executable authority | Terminal proof |
|---|---|---|
| `RC3-E1-machine-inventory` | `scripts/rc3_inventory.py` | Exact baseline/candidate Git objects and recomputed file, LOC, topology, and authority counts in an immutable external sidecar checked against an independently supplied candidate HEAD. The sidecar is not stored in the candidate tree because a tracked file cannot name its own containing commit. |
| `RC3-E2-prospective-slice-receipts` | `scripts/rc3_slice_receipt.py` | Immutable RC3 slice receipts; exact RC2 historical absence remains a waiver. |
| `RC3-E3-coverage-reproducibility` | `scripts/rc3_coverage.py` | Two exact-subject observations compare exactly or within the typed two-line tolerance. |
| `RC3-E4-portable-shell-scratch` | `scripts/test-scratch.sh` | Affected shell suites pass with constrained `TMPDIR` and scoped cleanup. |
| `RC3-E5-mechanical-candidate-budget` | `scripts/rc3_attempt_ledger.py`, `verification_receipt.py`, and `rc3_release_disposition.py budget` | `release-final` reserves an append-only, gap-free attempt before its first command and binds terminal state to actual receipt bytes; operator-authorized closure extends through attempt eight, and a ninth attempt is rejected. The authorization sidecar is bound by the final disposition digest. |
| `RC3-E6-typed-release-disposition` | `schemas/rc3-release-disposition-v1.schema.json` and its compiler | Canonically validated release-final receipt bytes, append-only ledger bytes, exact-head Fable/Codex callback+metadata pairs, accepted-deviation bytes, and an exact set of real finding-proof bytes compile approved or blocked. The compiler consumes the canonical review verdict/severity vocabulary and validates output against the published schema. |
| `RC3-E7-documentation-truth` | `tests/test_rc3_documentation.py` | Root, runtime, task, review, testing, release, and Russian handbook claims match executable entry points. |
| `RC3-E8-english-plan-contract` | `skills/implementation-plan/SKILL.md` | Normative plans default to English; explicit user language requests remain authoritative. |
| `RC3-E9-release-candidate` | repository release profile and immutable receipt | One clean exact-HEAD gate, complete reviews, aligned version carriers, and no post-verdict product drift. |

Focused tests establish their owned evidence only. The full RC3 outcome remains
blocked until the exact broad-gate receipt and both configured review verdicts
compile to an approved RC3-E6 disposition.

Exact-head inventory, attempt ledger, gate outputs, review callbacks, finding
proofs, accepted deviations, and final disposition are post-commit release evidence. They live under
one owner-controlled external evidence root and are attached to the release;
they are deliberately absent from the candidate Git tree so producing them
does not invalidate the HEAD they attest.
