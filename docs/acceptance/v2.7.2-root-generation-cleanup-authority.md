# 2.7.2 root-generation cleanup authority — exact candidate evidence

Scope: the bounded 2.7.2 class-level repair on the preserved 2.7.1 candidate
base `e62bd7f120ee95686d173128540eea4c90fc5f68` (three 2.7.1 commits consumed
as prerequisites, unchanged). One proven cleanup-authority regression is
repaired: resource closure binds to the immutable provider root generation
even when a later review callback target uses another generation. This note
claims no review acceptance, reap, merge, plugin installation, dogfood, tag,
or publication.

## Regression origin and repair

Origin: `2fcb6877` (`fix(harness): close exact review callback generation`)
deleted the `_ROOT_PROVIDER_GENERATION` binding in
`scripts/harness/runtime_session_cleanup.py` and rebound the close-receipt
`ResourceIdentity.generation` to the mutable callback-target generation; the
follow-up `_exact_result_stream` selector kept substituting the result
stream's generation as resource ownership. A missing immutable root generation
therefore completed cleanup and published `resource-closed.json` through a
live sibling stream instead of failing closed.

Repair (candidate commits on the task branch):

- `63a6778c` — RED delivery-boundary matrix: duplicate eligible root,
  malformed root directory, and symlinked root guards, plus the identity-drifted
  root case and the positive authority case asserting the durable close receipt
  binds `identity.generation == 1` while a later callback generation carries
  the accepted result. The pre-existing missing-root live-sibling reproducer is
  unchanged.
- `1203edf1` — the one-class fix: `_ROOT_PROVIDER_GENERATION = 1` restored;
  the new tiny private selector `_root_provider_stream` validates the root
  generation (real non-symlink directory, rehydratable, exact owner /
  operation / run / generation / process / workspace / surface identity) before
  any receipt or resource clearing; the close-receipt `ResourceIdentity` is
  minted only from the root generation; `_exact_result_stream` still validates
  callback result authority independently (unique candidate, accepted digest)
  but can no longer move resource ownership; the receipt event is consumed by
  the root stream, tolerating only `result-missing` when the exact later
  callback generation carried the validated result. The `test_store.py`
  review-parent fixture now mints the parent root generation stream, matching
  the production launch contract (`runtime_session_launch.py` mints
  `generation=1` at session start).

## Fail-closed matrix (all hermetic, `tests/harness/test_delivery_boundary.py`)

- Root and exact callback generation present → cleanup completes once and
  closes the root resource identity.
- Later callback generation with an accepted child callback → result authority
  accepted without moving resource ownership (receipt binds generation 1).
- Missing root despite an otherwise valid live sibling → typed attention, no
  receipt, resources retained.
- Duplicate eligible root contour, malformed generation directory, symlinked
  root, identity-drifted root, conflicting result digest, published result
  without an accepted callback, foreign durable close receipt → typed
  attention, no positive authority.
- Delegated review callback whose exact target generation stream is missing or
  mismatched, even when an earlier generation carries the accepted child
  digest → typed attention, no receipt, resources retained (Sol review
  correction; hermetic case in `tests/harness/test_store.py`). A callback
  already accepted by the parent record itself keeps its own durable
  earlier-generation contract.
- Root stream already latched in typed attention (`event-gap`,
  `deadline-reached`, or any reason beyond the tolerated `result-missing`)
  despite a valid later-generation result → typed attention with no durable
  close receipt and no `resource-closed` event (second Sol review round;
  hermetic `root-attention-latch` and `root-deadline-latch` cases).
- Symlinked closure authority ancestors — a symlinked `runtime` ancestor,
  operation state root, `provider-events` root, or `generation-1/delivery`
  directory — → typed attention, no receipt, and no write through the symlink
  target; every path component from the trusted store root through
  `owners/<owner>/runtime/<operation>/provider-events/generation-1` and its
  `delivery`/`events` leaves is validated without following symlinks, because
  `Path.is_symlink()` checks only the final entry (second and third Sol review
  rounds; hermetic `symlinked-provider-root`, `symlinked-delivery-authority`,
  `symlinked-runtime-ancestor`, and `symlinked-state-root` cases).
- Repeated cleanup after one valid receipt → `terminal` replay, no second
  closure effect.
