`RC4-E1-effective-topology` is bound at **dispatch**, not at review launch:
`dispatch_workspace` writes `review_topology` for every task whose review is
enabled, so no newly dispatched task is unbound. At the launch boundary,
`_assert_frozen_topology` fails closed on a binding that *disagrees* with the
compiled topology, but **tolerates a missing binding** so that records written
before the field existed, and current-checkout reviews that synthesize their
metadata at launch, can still start a review. The residual gap — an unbound v4
review-enabled record can launch a lane with no digest to compare against — is
recorded as D-266-RC4-02 in
`docs/acceptance/v2.6.6-rc4-accepted-deviations.json`.

## Review profile

By the operator's latest bounded routing decision, intermediate and final RC4
reviews use one single holistic Opus session at `high`. No intent/engineering
pair, cross-model fallback, extra reviewer, or hidden fix loop is authorized.
Any product edit after the verdict changes the HEAD and requires a new bounded
review boundary.

## User-owned release commands

The following block is fish-compatible and intentionally not executed by the
Harness:

```fish
set rc4_branch task/llm-obsidian-2-6-6-rc4-join
set rc4_tag v2.6.6-rc4
git switch main
git merge --ff-only $rc4_branch
git push origin main
git tag -a $rc4_tag -m "LLM Obsidian 2.6.6 RC4"
git push origin $rc4_tag
gh release create $rc4_tag --prerelease --title "LLM Obsidian 2.6.6 RC4" --notes-file docs/releases/v2.6.6-rc4.md
```

These commands merge, push, tag, and publish. They remain outside this task's
authorized effects. Plugin installation or update is likewise deferred until
after publication.
