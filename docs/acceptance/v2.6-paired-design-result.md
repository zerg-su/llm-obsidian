## Problem

An exact provider process and cmux surface can both be alive while the required
typed callback is absent. Process liveness alone does not distinguish quiet
work, a stable result awaiting ingestion, an interactive prompt, a callback
transport gap, or a true stall. Recovery must use the existing operation
identity and live ownership, preserve the 10/15/20-minute ladder, and become
typed attention when exact recovery is unsafe or exhausted.

The previous post-change result failed because it assigned nudge/restart
execution to `RuntimeSessionManager` and reported prototype output without
preserving runnable source. This decision treats both as explicit acceptance
boundaries.

## Non-goals

- Implement or refactor callback-stall recovery in production.
- Change the 60-second probe, 600/900/1200-second thresholds, two-read result
  stability rule, one-nudge limit, or one-restart limit.
- Add a scheduler, daemon, second pipeline engine, provider-specific lifecycle,
  dependency, schema, migration, public interface, or provider session.
- Infer ownership from focus, title, pane index, display text, or partial
  process identity.
- Ask a model to classify evidence or choose a deterministic transition.
- Broaden prompt automation, cleanup authority, review routing, or retry budget.

## Inspected facts, assumptions, and decision

### Facts

- [`OperationStore`](../../scripts/harness/store.py) owns the owner-scoped,
  locked, revisioned operation record. The record binds immutable spec/run/lane
  identity, exact resources, budgets, pending effect state, and accepted
  callback receipt.
- [`RuntimeSessionManager`](../../scripts/harness/runtime_sessions.py) creates
  the generic runtime session, opens and binds the exact surface, prepares the
  worker, binds returned process/supervisor identities, and exposes generic
  status, continuation, callback, exit, and cleanup interfaces. It does not
  retain the worker's live `ProcessHandle` used by liveness recovery.
- [`runtime_worker.py`](../../scripts/harness/runtime_worker.py) starts and
  retains that live `ProcessHandle`, owns the 60-second probe loop, collects
  prompt/process/result/callback evidence, invokes the liveness controller,
  sends the nudge to the exact surface, and terminates/restarts the exact child
  process group before rebinding resources. It is therefore the effect
  executor for the current nudge and restart paths.
- [`observe_liveness`](../../scripts/harness/liveness.py) is the pure decision
  seam. `LivenessPolicy.default()` is exactly
  `60, 600, 900, 1200, 1, 1, 2`; callback/receipt evidence suppresses recovery,
  two stable result reads choose model-free reconciliation, and an interactive
  or unknown prompt is not interrupted.
- [`LivenessController`](../../scripts/harness/liveness.py) persists
  content-free state and deterministic action receipts in owner-only runtime
  scratch. Those receipts support replay safety; they do not replace the
  operation ledger.
- [`OperationSupervisor`](../../scripts/harness/supervisor.py) persists the
  operation-global restart budget before the worker attempts a restart.
  [`provider_resume_argv`](../../scripts/harness/runtime_worker.py) requires an
  exact captured checkpoint.
- [`CallbackBroker`](../../scripts/harness/callbacks.py) is the one-shot typed
  callback admission owner. It validates exact operation/run identity and
  records callback id/kind/digest under the store owner lock.

### Assumptions

- Existing production behavior is the architecture being validated, not an
  implementation authorized by this document.
- `model_call: true` on `nudge` and `restart` describes the already-bounded
  effect on existing authorized work; transition selection itself remains a
  pure code path and starts no additional decision model or provider lane.
- Any later change to ownership, thresholds, budgets, schemas, or public
  interfaces requires a separate decision and implementation authorization.

### Decision / ADR candidate

**Retain one worker-owned callback-stall recovery vertical slice: the existing
runtime worker gathers exact evidence and executes live effects; the existing
pure liveness seam selects an action; `OperationStore` and
`OperationSupervisor` remain the durable lifecycle and budget authorities;
`RuntimeSessionManager` remains the generic setup/control facade; and
`CallbackBroker` remains the callback admission owner.**

This is the smallest composition that matches actual code ownership. It adds no
new component, operation kind, provider path, model decision, or durable truth.

## Invariants

1. One immutable owner/operation/run/lane identifies the decision; resource
   effects additionally require the recorded exact surface, process group,
   process identity, supervisor identity, and restart checkpoint.
2. `OperationStore` is the sole lifecycle authority. Liveness scratch may hold
   content-free counters/action receipts but cannot accept a callback or invent
   a legal transition.
3. The runtime worker is the only liveness nudge/restart executor because it
   owns the current `ProcessHandle`. `RuntimeSessionManager` must not be named as
   executor merely because it exposes higher-level lifecycle methods.
4. Callback or receipt evidence preempts recovery. A stable typed result uses
   the existing callback-specific reconciliation path without a decision-time
   model call.
5. Unknown process state, unknown/interactive prompt state, invalid checkpoint,
   mismatched resource identity, exhausted budget, or failed effect becomes
   observation or typed attention, never an ownership guess.
6. The ordering stays fixed: suspected idle at 10 minutes; at most one nudge at
   15 minutes; at 20 minutes, restart only after the nudge opportunity has been
   consumed; then typed attention. A dead provider may use the same single
   restart budget through the existing adjacent branch.
7. Decision evidence contains identifiers, revisions, states, timestamps,
   counters, and digests—not screen text, callback bodies, or prompts.
8. Deterministic action selection is pure and code-owned. Only the already
   authorized nudge/restart effects may resume model work after selection.
9. Production code, dependencies, harness, skills, schemas, the paired
   manifest, and fixtures remain unchanged by this validation.

## Ownership boundaries and interfaces

| Boundary | Owned contract | Explicitly not owned |
|---|---|---|
| `OperationStore` + state machine | Immutable operation identity, revisioned legal transitions, exact resources, callback receipt, budget/effect fields | Provider handle, screen bodies, scheduling |
| `RuntimeSessionManager` | Route preflight, surface/worker launch, durable resource binding, status/continue/callback/exit/cleanup facade | Current liveness decision or worker-local nudge/restart execution |
| Runtime worker | Live `ProcessHandle`, probe cadence, exact evidence collection, liveness dispatch, exact-surface nudge, identity/checkpoint-bound child restart | New lifecycle, provider-specific policy, ownership discovery by UI heuristics |
| `observe_liveness` | `(previous state, evidence, fixed policy) -> (decision, next state)` | I/O, wall-clock reads, store writes, cmux/process effects, model calls |
| `LivenessController` | Owner-only decision state and deterministic action receipts | Authoritative operation state or callback receipt |
| `OperationSupervisor` | Persisted attempt/time/token/restart budgets and generic effect boundary | Live child handle or decision policy |
| `CallbackBroker` | Exact one-shot callback acceptance and legal callback-driven transition | Liveness timing, nudge/restart, cleanup |
| Coordinator/operator | Inspect and resolve typed attention through existing harness lifecycle | Routine recovery effects or ownership guesses |

The private interfaces are already present and need no new schema:

```text
observe_liveness(previous, evidence, policy) -> decision, next_state
LivenessController.observe(evidence, policy) -> decision + persisted receipt
OperationSupervisor.consume_model_restart(explicitly_permitted=True)
CallbackBroker.accept(exact CallbackEnvelope)
RuntimeSessionManager.status / continue_session / accept_callback / request_exit / cleanup
```

## Alternatives

### A. Worker-owned vertical slice with a pure decision seam — selected

Keep the existing worker as both evidence collector and live-effect executor,
while `observe_liveness` stays independently testable and the store/supervisor
keep durable authority. This matches the actual handle lifetime, adds no engine,
and keeps provider-specific command construction below generic policy. The
trade-off is that worker failure containment and exact-resource diagnostics
remain important acceptance seams.

### B. Make `RuntimeSessionManager` execute liveness nudge/restart — rejected

The manager launches the worker and records stable identities, but the worker
creates and retains the live `ProcessHandle` and currently performs signals,
restart, and resource rebinding. Assigning the effects to the manager would
either be factually wrong or require a new control protocol and ownership
transfer. That was the material defect in the stopped validation.

### C. Add a coordinator/watchdog recovery loop — rejected

A separate loop would duplicate cadence, counters, callback observation,
ownership reconciliation, and failure handling. It would be a second lifecycle
authority or scheduler and would create races with the existing worker. It also
increases pressure to guess ownership from focus or surface presentation.

## Recommendation and control flow

No production change is recommended for this release candidate. Treat the
current composition as the required architecture boundary:

```text
RuntimeSessionManager launches worker and binds exact durable resources
                              |
                              v
runtime worker owns live handle + 60-second probe
                              |
        exact content-free LivenessEvidence
                              |
                              v
      observe_liveness / LivenessController (pure choice + receipt)
        |            |             |              |
        v            v             v              v
   observe /     reconcile      nudge          restart / attention
  suspected-idle   result    exact surface   exact child + checkpoint
        |            |             |              |
        |            v             |              v
        |       CallbackBroker     |       OperationSupervisor budget
        |            |             |              |
        +------------+-------------+--------------+
                              |
                              v
                  one OperationStore ledger
```

Decision precedence and effects:

| Evidence | Pure decision | Existing executor/effect |
|---|---|---|
| Current callback or receipt digest | `observe` | Callback path continues; no recovery effect |
| Same typed-result digest on two reads | `reconcile-result` | Worker invokes existing typed callback/result inspection; no model call |
| Process dead, restart unused | `restart` | Worker consumes supervisor budget and resumes exact checkpoint |
| Process/prompt unknown or prompt interactive | `observe` | None |
| Alive/non-interactive and quiet 10 minutes | `suspected-idle` | Content-free receipt/telemetry only |
| Quiet 15 minutes, nudge unused | `nudge` | Worker sends one bounded message to recorded exact surface |
| Quiet 20 minutes, nudge used, restart unused | `restart` | Worker terminates exact child group, resumes checkpoint, rebinds resources |
| Recovery exhausted | `attention-required` | Worker records `retry-exhausted` through the store |

If a probe first arrives after 20 minutes with the nudge unused, policy still
chooses the nudge before restart. The next eligible probe may restart; the
ladder never skips its one bounded nudge opportunity.

## Failure recovery

| Failure or race | Required existing behavior |
|---|---|
| Callback/result appears before a recovery probe | Digest evidence suppresses recovery; exact callback admission remains broker-owned |
| Typed result is present but callback publication stalled | Two stable reads select the existing model-free result reconciliation path |
| Prompt is interactive or its state cannot be proved | Observe only; prompt automation remains separately constrained |
| Provider process is dead | Use at most the same one persisted restart budget and exact checkpoint; otherwise attention |
| Restart checkpoint is absent/invalid | `provider_resume_argv` rejects; worker moves the operation to typed attention |
| Nudge send fails or worker dies after its decision receipt | The persisted nudge counter prevents a second nudge; later evidence can only progress toward the existing restart/attention boundary |
| Restart fails before a new exact handle is bound | Restart budget was already consumed; worker records typed attention rather than blind retry |
| Resource identity is missing, stale, or unknown during later lifecycle work | Existing status/reconciliation fails closed; no signal or close from guessed ownership |
| Callback deadline expires independently of the liveness ladder | Existing passive deadline path may record `callback-timeout`; it does not become a second nudge/restart executor |
| Budget is exhausted | Durable `attention-required`; release acceptance stops if this design would require broader authority |

## Bounded pure-decision prototype

### Question

Does the current pure `observe_liveness` seam enforce the frozen
10/15/20-minute ladder, callback/interactive suppression, stable-result
reconciliation, and exhausted attention while marking only the already-bounded
nudge/restart effects as model work?

### Pass/fail criterion

One command against the exact release candidate must satisfy ten assertions
over eight cases. The action sequence must be:

```text
suspected-idle, nudge, restart, attention-required,
observe(callback), observe(interactive), observe(first result), reconcile-result
```

Exactly two rows may report `model_call: true`: the existing nudge and restart
effects. Any other sequence, repeated budget, or assertion failure is a fail.

### Preserved runnable source

```python
#!/usr/bin/env python3
"""Pure-decision probe for the frozen callback-stall recovery ladder."""

from __future__ import annotations

import json
import sys
from dataclasses import replace
from pathlib import Path


repo = Path(sys.argv[1]).resolve()
sys.path.insert(0, str(repo / "scripts"))

from harness.liveness import (  # noqa: E402
    LivenessEvidence,
    LivenessPolicy,
    LivenessState,
    observe_liveness,
)


policy = LivenessPolicy.default()
base = LivenessEvidence(
    observed_at=1000,
    process_status="alive",
    operation_revision=7,
    operation_state="awaiting-callback",
    screen_sha256="a" * 64,
    prompt_state="non-interactive",
)
state = LivenessState.start(base)
rows: list[dict[str, object]] = []


def probe(
    label: str,
    previous: LivenessState,
    evidence: LivenessEvidence,
    expected: str,
) -> LivenessState:
    decision, current = observe_liveness(previous, evidence, policy)
    assert decision.action == expected, (label, decision.action, expected)
    rows.append(
        {
            "case": label,
            "action": decision.action,
            "model_call": decision.model_call,
            "nudges": current.nudge_count,
            "restarts": current.restart_count,
        }
    )
    return current


idle = probe("10m", state, replace(base, observed_at=1600), "suspected-idle")
nudged = probe("15m", idle, replace(base, observed_at=1900), "nudge")
restarted = probe("20m", nudged, replace(base, observed_at=2200), "restart")
probe("exhausted", restarted, replace(base, observed_at=2260), "attention-required")
probe(
    "callback-present",
    restarted,
    replace(base, observed_at=2260, callback_sha256="b" * 64),
    "observe",
)
probe(
    "interactive",
    nudged,
    replace(base, observed_at=2200, prompt_state="interactive"),
    "observe",
)
first_result = probe(
    "typed-result-first-read",
    state,
    replace(base, observed_at=1060, typed_result_sha256="c" * 64),
    "observe",
)
probe(
    "typed-result-stable",
    first_result,
    replace(base, observed_at=1120, typed_result_sha256="c" * 64),
    "reconcile-result",
)

assert [row["action"] for row in rows] == [
    "suspected-idle",
    "nudge",
    "restart",
    "attention-required",
    "observe",
    "observe",
    "observe",
    "reconcile-result",
]
assert sum(bool(row["model_call"]) for row in rows) == 2
print(json.dumps({"assertions": 10, "rows": rows}, sort_keys=True))
```
