# v2.9.6 acceptance boundary

The user requested a fix and release in the ordinary public `llm-obsidian`
repository. The release starts from v2.9.5 (`1f0244a8`); historical cleanup and
private vault content are outside this change.

## Behavior and regression evidence

The regression originally reproduced a completed, harness-owned worktree left
on disk after result filing and provider shutdown. The fix adds cleanup at
that exact boundary, keeps branches/commits, and stores a small durable receipt
outside the checkout. It never uses force removal or scans historical copies.

`python3 tests/test_reap_worktree_cleanup.py` exercises real Git repositories
and worktrees, the real harness operation store and callback workflow, with a
fake provider and bounded finalization fixture. It covers v3/v4, final/shared
plans, committed branch preservation, tracked/staged/index-hidden changes,
unknown untracked/ignored files, owned runtime artifacts, lock/ownership and
live-binding guards, coordinator CWD, detached HEAD, symlinks, completion
proof, provider failure, Git failure, replay after deletion, reused paths,
wrong coordinators, crash recovery, and the public CLI replay.

The advisory Light Review found one missing guard: a clean checkout can retain
an unfinished Git sequencer after manually committing a conflict resolution.
A real two-commit cherry-pick regression reproduced deletion before the fix.
Cleanup now retains sequencer, revert, and bisect state alongside existing
merge/rebase/cherry-pick guards. The reviewer inspected all six engineering
sections; it did not run tests or grant Lifecycle approval.

## Limits

Unknown pipeline output files and legacy/unowned checkouts are intentionally
retained with a reason. There is no automatic historical sweep, branch pruning,
or claim that ignored files are generally disposable. Runtime receipts are
stored under the already ignored `.vault-meta/harness/` tree.
