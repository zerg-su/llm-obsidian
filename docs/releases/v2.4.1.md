# LLM Obsidian v2.4.1

Version 2.4.1 completes the executable `engineering/fix` profile that 2.4.0
only described. It keeps the 2.3 harness as the sole runtime engine: one
`OperationStore`, one state machine, one provider supervisor, and one
coordinator-owned review/reap lifecycle.

## Highlights

- `engineering/fix` is a real persistent-session pipeline:
  `reproduce` → `root-cause` → `regression-test` → `minimal-fix` → verify →
  review → reap-ready.
- Every model phase is a resource-less child `OperationSpec` in the parent
  lane. The model writes a bounded result; `pipeline-step-submit.py` emits one
  exact callback envelope; the harness alone accepts an immutable typed
  receipt.
- Recovery reconstructs the first missing phase from accepted receipts.
  Accepted model phases and accepted protected-research stages are never
  replayed.
- Verification failure enters a typed bounded fix loop. `attention` permits
  two total passes; explicitly approved `autonomous` permits three. Mechanism,
  callback, permission, and security failures still return typed attention.
- `cannot-reproduce` creates one durable `pipeline-decision` packet bound to
  the accepted reproduction receipt. It offers only `stop` or
  `retry-with-fixture` and wakes the exact originating coordinator once.
- An interrupted fix provider can consume the parent operation's persisted
  restart budget and relaunch with the exact frozen argv, environment, and
  cmux surface. The reconciler resumes from the first missing receipt instead
  of replaying accepted phases.
- The selected completion policy freezes the actual runtime attempt, restart,
  time, and token envelope before provider launch.
- An early `.task-summary.json` cannot bypass unfinished model phases. After
  the final accepted phase, the same executor session receives one finalization
  prompt and the existing verification/review/reap path resumes.
- Compiled-pipeline telemetry now records only bounded identifiers, hashes, and
  numeric counters: pipeline/version/profile, compiler outcome, definition
  digest, primitive count, loop iteration, and terminal/attention category.
- Protected research has explicit shadow-parity evidence for the shared
  operation store, supervisor, runtime callback seam, typed artifacts, and
  replay behavior. No research DSL or second controller was added.
- Claude review scratch permits a small exact read-only probe set for Git
  inspection and bounded project checks. It does not grant wildcard commands,
  chaining, network, or product writes.

## Boundaries

- No model-authored or user-authored pipeline DSL; that remains a 2.5 decision.
- No second workflow engine, scheduler, durable progress store, FSM,
  supervisor, or operation identity.
- No compatibility adapter for active 2.4.0 operations. Finish or cancel them
  with the installed checkout before upgrading.
- `reap` remains coordinator-owned. Push, publish, deploy, worktree deletion,
  and scope expansion remain outside unattended task authority.
- A broader OS-isolated reviewer probe profile remains deferred to 2.5. The
  exact read-only allowlist is the deliberate 2.4.1 boundary.

## Clean install

```bash
git clone --branch v2.4.1 https://github.com/zerg-su/llm-obsidian.git
cd llm-obsidian
bash bin/setup-clean-machine.sh

python3 scripts/codex-adapter.py --check
scripts/mcp-gateway/mcp-gateway.sh codex-sync --check
python3 scripts/harness-cli.py doctor
```

Install the local marketplace/plugin through Claude Code. For Codex:

```bash
codex plugin marketplace add "$(pwd)"
codex plugin add llm-obsidian@llm-obsidian-codex
```

Start a new Claude/Codex thread after installation so the host loads the
2.4.1 skill registry.

## Upgrade from 2.4.0

Finish or cancel every active task, review, research, and reap operation before
changing the checkout:

```bash
python3 scripts/upgrade-preflight.py --vault-root .
git pull --ff-only
python3 scripts/codex-adapter.py --apply
scripts/mcp-gateway/mcp-gateway.sh codex-sync --apply
python3 scripts/harness-cli.py doctor
```

The operation schema stays version 1, but an operation must complete under the
checkout that started it.

## Release gate

Model-free checks:

```bash
make test
make acceptance-check
python3 scripts/validate-vault.py --summary
python3 scripts/codex-adapter.py --check
scripts/mcp-gateway/mcp-gateway.sh codex-sync --check
git diff --check
```

Before tagging, the checked-in dogfood report must account for at least ten
completed compiled tasks across both executor runtimes, both engineering
profiles, simple/deep review, one bounded retry, one controlled provider
restart, and one deliberate typed escalation. There must be no unresolved
callback failures or auto-close misses.

## Rollback

Finish or cancel active 2.4.1 operations, then reinstall 2.4.0 and refresh both
adapters:

```bash
git switch --detach v2.4.0
python3 scripts/codex-adapter.py --apply
scripts/mcp-gateway/mcp-gateway.sh codex-sync --apply
python3 scripts/harness-cli.py doctor
```

## Maintainer release commands

Run only after the final review and release checks are green:

```fish
set RELEASE_SHA (git rev-parse HEAD)
test (count (git status --porcelain)) -eq 0

git push origin main
set REMOTE_SHA (git ls-remote origin refs/heads/main | string match -r '^[0-9a-f]+')
test "$REMOTE_SHA" = "$RELEASE_SHA"

git tag -a v2.4.1 $RELEASE_SHA -m "LLM Obsidian v2.4.1"
git push origin v2.4.1
git ls-remote --exit-code origin refs/tags/v2.4.1

gh release create v2.4.1 \
  --repo zerg-su/llm-obsidian \
  --title "LLM Obsidian v2.4.1" \
  --verify-tag \
  --notes-file docs/releases/v2.4.1.md
```
