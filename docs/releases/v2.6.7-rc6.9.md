# LLM Obsidian v2.6.7 RC6.9

RC6.9 separates task evidence available to implementation review from later
coordinator acceptance evidence and makes supported live-provider cancellation
converge within one bounded public action. It changes no public schema, review
verdict policy, provider replay authority, or ordinary reap terminal state.

## Review evidence boundary

- Implementation-plan, save-plan, and review authoring require canonical task
  success evidence to be reviewer-observable before the configured verdict.
- Review callbacks, Wiki Summary acceptance, reap, release promotion, and
  terminal resource proof remain parent-owned post-review gates outside the
  task Outcome Contract.
- Strict missing-evidence review behavior remains unchanged; a circular task
  contract is returned for amendment.

## Bounded terminal cancellation

- One supported `harness cancel` requests provider exit once, observes exact
  identity-bound cleanup within a fixed budget, clears owned resources, and
  terminates honestly as `cancelled` when cleanup is proved.
- An operation that remains nonterminal returns exit status `3` with typed
  `partial` output. No second cancel/resume action or provider replay is hidden.
- Exact surface close is re-probed. A live, unknown, or otherwise unproved
  surface retains ownership and becomes `cleanup-incomplete` rather than being
  guessed closed. The shared ordinary cleanup path still terminates as
  `complete` when proof succeeds.
- Provider disappearance is expected only for the matching run durably in
  `exiting`, with no pending effect and succeeded `request-exit`; sibling states
  remain fail-closed.

## Candidate boundary

The live scripts ratchet is pinned to the exact RC6.9 denominator of 288 Python
files / 107,656 lines. Post-review merge, plugin refresh, built-in/custom
dogfood, reap, and promotion remain coordinator-owned. This candidate does not
push, tag, publish, update plugins, or run live dogfood.
