# LLM Obsidian v2.6.3

Version 2.6.3 is a documentation-first patch release. It adds a complete
Russian technical handbook and deterministic documentation evidence while
preserving the 2.6.2 runtime, permission, provider, fallback, and pipeline
contracts outside four exact regression-covered repairs: accepted research
callback cleanup, default MCP runtime-config bootstrap, quiescent mixed-HEAD
review recovery, and terminal legacy-round compatibility during that recovery.

## Russian technical handbook

[`docs/ru/index.md`](../ru/index.md) provides four explicit routes:

- installation to a first durable vault result;
- recurring user/operator work, safe recovery, and all 34 shipped skills;
- built-in and custom PipelineSpec authoring with a complete v1 field reference;
- maintainer change, tests, extension decisions, upgrade, rollback, and RC gates.

Fourteen instructional pages share prerequisites, a complete example, expected
result and independent verification, failure/recovery, and source-of-truth
sections. The handbook links to authority rather than replacing `AGENTS.md`,
`CLAUDE.md`, schemas, compiler policy, configuration, or tests.

## Protected research and callback repair

The documentation baseline adopts/adapts/rejects claims from eight isolated
fetched sources: Diátaxis, Google Audience and LLM writing guidance, GitLab docs
testing, GitHub versioning, Google code samples, WCAG 2.2, and NIST AI 600-1.
The synthesis artifact cited a ninth unfetched URL and was rejected entirely.

The research lifecycle repair preserves an accepted research callback as
completion during exact cleanup. A cancelled fetch receipt may recover only
when its parent remains nonterminal and callback digest, run, request, and
artifact identities match exactly. A mismatch creates no synthesis child and
starts no provider. A terminal parent is rejected before artifact preparation,
synthesis child creation, surface allocation, or provider start; it is never
reset or replaced. Cancelled-synthesis recovery remains removed. Cancellation
without an accepted callback still ends as `cancelled`.

The separately classified bootstrap mechanism repair allows only
`mcp-gateway.sh sync-config --apply`, with no custom runtime override, to create
a missing default `scripts/mcp-gateway/runtime.env`. Bytes come only from the
committed sibling example after strict single-port validation, through the
existing atomic writer with mode 0600. Check/print paths, direct config-sync,
custom paths, missing/invalid examples, runtime/example symlinks, and every
other gateway subcommand remain write-free and fail closed.
Coordinator decision `70acb04f-5542-4e90-9466-94193b369181` authorizes this
second, narrowly bounded runtime exception and its new default-path write
authority; it does not change provider, permission, network, or pipeline policy.

The review recovery facade now accepts a mixed-HEAD `awaiting-resolution` gate
only after exact coordinator authorization and proof that every retained parent
and current round is terminal, resource-free, and has no pending effect. It then
uses the existing attention/fresh-boundary path with a zero-iteration
verification budget. Live ownership, non-empty final results, prior fresh use,
or any identity drift still fails before a provider effect.

Recovery can also read historical terminal round records created before
`parent_operation_id` became durable. The compatibility adapter is recovery-only
and in-memory: it accepts only the exact operation/lane/run/idempotency identity
when the missing parent field is the sole specification difference. It never
rewrites the stored record; live, resource-owning, pending-effect, or otherwise
different records remain rejected.

## Upgrade from 2.6.2

Finish or reconcile live operations before updating. After obtaining the new
repository bytes through the user's normal approved Git workflow:

```bash
python3 scripts/upgrade-preflight.py --root .
python3 scripts/codex-adapter.py --apply
scripts/mcp-gateway/mcp-gateway.sh codex-sync --apply
python3 scripts/harness-cli.py doctor
make test-docs
```

Start a new Claude/Codex session so the host reloads generated metadata. No
state migration is required.

```bash
scripts/mcp-gateway/mcp-gateway.sh codex-sync --check

git diff --check v2.6.2..HEAD
```

These commands prepare and validate a candidate. They do not authorize or
perform push, tag, publish, deploy, or release.

## Rollback

Because no schema, permission, provider, or state migration is introduced,
rollback returns to the approved 2.6.2 repository/plugin bytes through the
normal versioned installation path, reruns adapter sync and the release gate,
and leaves existing operation records and vault data unchanged. If an active
operation has ambiguous upgrade state, stop at `attention-required` instead of
rewriting its store.
