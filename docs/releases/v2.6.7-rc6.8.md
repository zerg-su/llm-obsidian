# LLM Obsidian v2.6.7 RC6.8

RC6.8 closes the exact actor-authority mismatch between the policy-valid
custom-start snapshot emitted by RC6.7 and the existing frozen custom-pipeline
boundary. It changes no public schema, lifecycle, recovery, callback, provider,
model, or cleanup authority.

## Exact policy-valid freeze authority

- `freeze_custom_pipeline()` accepts `policy-valid-snapshot` only alongside
  the existing `user` and `host-user-dialog` actors, and only for an exact
  `approve` decision.
- The existing compiled-definition and approval-card hashes remain mandatory.
  Unknown/model actors, reject or revise decisions, definition drift, and card
  drift still fail closed.
- The retained host-dialog and one-shot approval-token path is unchanged.

## Continuous production boundary

The production-shaped dispatch regression now crosses request validation,
owner-only immutable snapshot persistence and consumption,
`authorize_custom_request()`, and `custom_pipeline_for_request()` freeze
preparation as one path. The successful policy-valid path needs no host token
and reaches no worktree, provider, or model subprocess before start.

The same boundary rejects missing or reused snapshots and request, plan, spec,
definition, approval-card, route, review, session, permission, side-effect,
budget, or actor drift before those effects.

## Candidate boundary

Post-install custom dogfood remains separate coordinator-owned evidence after
merge and plugin refresh. RC6.8 does not merge, push, tag, publish, update
plugins, run that dogfood, delete legacy approval code, or promote the final
release.
