# LLM Obsidian v2.6.7 RC4

Candidate version: `2.6.7-rc4`.

RC4 is a terminal-only dashboard candidate built on the exact RC3 product
base. It refines the existing external, read-only Harness observer; it does not
add a browser, server, daemon, timestamp writer, or lifecycle primitive.

## Terminal hierarchy and color

- Normal live mode remains a human-readable, root-scoped product view. Its
  title/store/update/rule lead into one task-name-first root summary, one
  executor summary, the compiled step tree, bound current-work detail, recent
  terminal roots, bounded issues, a final rule, and the legend.
- The owner-wide diagnostic remains explicit and diagnostic-only. It does not
  become the default observer. Classification/program counts, revisions,
  definition hashes, raw controls/loops, lanes, and unbound-child bookkeeping
  stay there instead of leaking into the normal root view.
- Completed and upcoming steps are compact. Exactly current work is expanded
  and bold, with visible symbols and English labels retaining every state fact;
  the diagnostic view retains the legacy ASCII markers as well.
- The semantic palette uses 24-bit ANSI foreground colors only. `--no-color`
  emits no escapes, and stripping ANSI from a colored frame yields the same
  text as its plain frame.

## Display-only time and review evidence

- Root elapsed time and terminal duration come from exact durable timestamps:
  bound task metadata and validated reap completion, with bound liveness as the
  active-root fallback.
- Verification duration uses only the already accepted verification interval.
  Exact active children can supply elapsed time; terminal model, review, and
  fix work with no authoritative end uses one compact dash. The expanded
  current row says `time unavailable`; upcoming rows omit timing instead of
  repeating unknown noise.
- Malformed, future, reversed, stale, leaf-symlinked, ancestor symlink, or
  identity-mismatched evidence is rejected. Best-effort event telemetry,
  deadlines, screen text, file order, and mtimes never become display truth.
- Review cycle, bounded limit, total findings, and material findings are shown
  only from a validated exact attempt whose gate, HEAD, axes, lane, run, and
  attempt are structurally bound, together with bound notification evidence.
  The dashboard never reads review prose or callback bodies.
- One wall-clock value is sampled per frame at the outer adapter. This clock is
  display-only and has no lifecycle authority; it cannot affect status,
  classification, next action, retries, readiness, issues, or persisted state.

## Preserved boundary

The root-scoped split remains external and user-owned. Projection and rendering
remain read-only. The owner-wide diagnostic path, `--no-color` behavior,
unknown evidence semantics, and every RC3 dispatch/review/verification/
recovery/callback/cleanup/reap invariant remain in force.

This candidate still requires the planned independent review of its exact local
HEAD. Approval is not claimed here, and the candidate is not tagged or
published by this work. No push, merge, deployment, or release effect is part
of this implementation.
