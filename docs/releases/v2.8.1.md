# LLM Obsidian v2.8.1

Version 2.8.1 stabilizes the Harness lifecycle and verification continuation
paths exercised after the 2.8.0 release. It is a patch release: public skill
semantics and the Architecture Workflow v1 artifact contract are unchanged.

## Lifecycle and verification fixes

- Accepted nested review callbacks survive the observed post-accept
  `callback-invalid` boundary without replaying reviewer or provider effects.
- Exact-HEAD verification, canonical-summary refresh, review admission, and
  superseded predecessor receipts retain one durable authority chain across
  restart and finalization.
- Typed verification escalation exposes only decisions valid for the exact
  escalation kind, and the registered authorized-continuation path preserves a
  failed full-profile receipt before a fresh review boundary.
- Verification attention packets and changed-HEAD resubmission responses are
  published atomically. A worker that already bound the failed HEAD now defers
  an exact response for the current clean successor to the next ordinary
  reconciliation pass instead of rejecting it as a malformed same-HEAD retry.

## Regression and release evidence

- The changed-HEAD race is forced deterministically in the production summary
  corridor; the test proves the failed receipt, accepted response, exact
  successor verification, and review handoff without `callback-invalid`.
- The complete Harness suite (97 registered files), model-routing suite,
  code-quality audit, and exact live scripts ratchet pass on the release
  candidate. Code quality reports zero release blockers.
- A fresh ordinary Sol High implementation review approved the exact repair
  HEAD after independently rerunning the scoped profile.
