# LLM Obsidian v2.6.2

Version 2.6.2 makes the cmux workspace progress projection truthful while
preserving the existing harness lifecycle, provider parity, and fail-closed
ownership boundaries.

## Truthful workspace progress

- The content-free bar selects only nonterminal top-level dispatch, review, and
  research controllers whose exact origin belongs to the target coordinator
  workspace.
- A terminal controller authoritatively closes its program, so stale derived
  operations cannot retain a false progress line.
- One two-second-bounded exact cmux tree snapshot verifies origin placement and
  live owned surfaces. The single adapter-owned decoder uses UUID identity,
  skips unrelated malformed entries, and marks ref-only or conflicting
  placements as attention instead of guessing or clearing to false idle. Any
  controller with a recorded exact surface that is known missing is not current
  workspace work; an unknown or timed-out probe leaves the previous UI untouched
  and changes no durable state.
- An empty selection issues workspace-scoped `clear-progress`. Coordinator
  SessionStart refreshes the projection; task-worktree SessionStart remains
  suppressed.
- Claude and Codex share the same counts-only label:
  `completed/total · active▶`, with optional waiting `⌛` and attention `!`.

This remains harness-step status, not task/backlog progress. No scheduler,
daemon, historical OperationStore rewrite, rate-limit widget, pipeline DSL, or
new lifecycle authority is introduced.

## Preserved bounded repairs

The release retains the turn-end save-and-close repair from `80fcab2`: Claude
and Codex can run the synchronous queue-session-exit path before process exit,
and blocked validation still refuses to close. It also retains the ordinary
provider launch repairs from `0630477` and `966dca1`: parent preflight pins the
exact trusted env-shebang interpreter before entering a new cmux surface, and
an ordinary runtime requires its exact product root to equal `cwd` even when
the child `PATH` cannot resolve Node. The integration HEAD also retains the
bounded hot-thread cache eviction fix from `69e2dae`, so a full Active Threads
cache evicts the oldest entry instead of rejecting a new current thread.

The clean-HEAD acceptance gate classifies only the exact harness-owned
`.task-pipeline` request/callback transport namespace as non-behavioral runtime
state. Source, documentation, configuration, test, and unknown dirt still
block release acceptance.

## Rollback

The `v2.6.2` tag must point to the no-fast-forward merge of `release/2.6.2`
whose first parent is the published 2.6.1 HEAD. Roll back that atomic release
boundary with `git revert -m 1 v2.6.2`, run the release gate, and reinstall
adapters. Operation records are unchanged, so rollback requires no state
migration. The old projection may again retain stale progress, but lifecycle,
callback, cleanup, and ownership state remain authoritative. If the tag does
not have that topology, stop rather than attempting a partial range revert.

## Maintainer release commands

Run only after the exact release branch HEAD is clean and approved. The merge
and the two parent/tree assertions are part of the release gate: they create
the atomic rollback topology instead of assuming it already exists.

```fish
set CANDIDATE_SHA (git rev-parse release/2.6.2)
test (count (git status --porcelain)) -eq 0

git switch main
git pull --ff-only origin main
set PRE_RELEASE_SHA (git rev-parse HEAD)
test "$PRE_RELEASE_SHA" = (git rev-parse 'v2.6.1^{commit}')

git merge --no-ff release/2.6.2 -m "Merge LLM Obsidian v2.6.2"
set RELEASE_SHA (git rev-parse HEAD)
test (git rev-parse "$RELEASE_SHA^1") = "$PRE_RELEASE_SHA"
test (git rev-parse "$RELEASE_SHA^2") = "$CANDIDATE_SHA"
test (git rev-parse "$RELEASE_SHA^{tree}") = (git rev-parse "$CANDIDATE_SHA^{tree}")
test (count (git status --porcelain)) -eq 0

git push origin main
set REMOTE_SHA (git ls-remote origin refs/heads/main | string match -r '^[0-9a-f]+')
test "$REMOTE_SHA" = "$RELEASE_SHA"

git tag -a v2.6.2 $RELEASE_SHA -m "LLM Obsidian v2.6.2"
git push origin v2.6.2
git ls-remote --exit-code origin refs/tags/v2.6.2

gh release create v2.6.2 \
  --repo zerg-su/llm-obsidian \
  --title "LLM Obsidian v2.6.2" \
  --verify-tag \
  --notes-file docs/releases/v2.6.2.md
```
