# LLM Obsidian v2.8.6

Version 2.8.6 replaces coordinator-centered and per-reviewer cmux placement
with a task-centered two-workspace topology. Harness execution, review
cardinality, model routing, verdict semantics, and the five-cycle finalization
ceiling remain unchanged.

## Primary task workspace

- Dispatch creates and durably binds the task surface, workspace, and window
  before opening exactly one root dashboard split from that task surface.
- The executor, dashboard, verification, fixes, recovery, and all other
  non-review continuations remain in the primary task workspace.
- The coordinator workspace stays separate and receives no task dashboard
  split. The obsolete temporary dashboard and rebind step is removed.

## Shared review workspace

- Each review program creates one separate workspace. Its first reviewer is the
  exact launch anchor; later Simple, Deep, and Full lanes open as splits in the
  same workspace after validating workspace/window UUID membership.
- Review finalization and structural pivot use the program's workspace. A later
  review cycle creates a fresh workspace; executor fixes continue in the
  primary task workspace.
- Lane cleanup closes individual reviewer surfaces. The shared workspace closes
  only after all callbacks, finalization, provider exits, and lane cleanup have
  succeeded. The third material failure retains it through structural pivot.

## Exact terminal cleanup

- Review and reap cleanup persist exact, idempotent workspace closure receipts.
  An already-gone exact UUID is success.
- Unknown, duplicate, moved, foreign, or incomplete ownership fails closed and
  retains the relevant workspace for diagnosis.
- Successful reap first clears task-provider ownership, then closes the exact
  primary workspace including its dashboard.

## Evidence

- A provider-free state-machine oracle covers dispatch, Simple/Deep/Full
  fan-out, changes-requested fixes and fresh cycles, approval/reap, attention,
  and concurrent independent tasks.
- Focused dispatch, dashboard, review topology, exact-HEAD, structural-pivot,
  runtime cleanup, delivery-boundary, task-session, and reap suites cover the
  production transitions and UUID authority.
- The release gate includes `make test-harness`, `make test-model-routing`, and
  the complete `make test` suite.
- The active review authority contour is pinned to the exact 28-file / 16,421
  LOC candidate with zero writable authorities, zero incident literals, and no
  headroom. The complete scripts contour is exactly 297 files / 113,722 lines.
