# LLM Obsidian v2.6.6 RC2

RC2 is a narrow repair-and-delete polishing candidate over
`v2.6.6-rc1-fix2`. It reduces the active lifecycle surface and does not add a
provider route, scheduler, state machine, background model call, or Vault Sync.

## Repaired ownership

- Verification receipts are accepted only for the exact subject HEAD and
  profile whose commands, exits, output sizes, and output digests they record;
  later byte tampering invalidates scoped recovery evidence.
- Implementation-review authority parses the complete immutable bundle (or
  complete v2 evidence set) before launch; missing sidecars, unknown profiles,
  parent subjects, changed bytes, and path escapes fail closed.
- Callback acceptance persists its state transition and accepted identity
  through one public atomic Store seam, and a stale duplicate cannot bypass
  immutable operation/run identity checks.
- Recovery of an already accepted, resource-free review dispatch completes
  finalization once; duplicate wakeups do not replay provider, callback,
  verification, process, or cmux effects.
- A crash after durable terminal approval can resume from either
  `attention-required` or `finalizing` and terminalize the same dispatch without
  replaying any external effect.

## Smaller runtime contour

The frozen baseline proved seven files had zero production callers. RC2 removes
all seven: six classic supervisor/watchdog/trust modules and the conditional
review-archive wrapper. That is 2,217 physical lines from the frozen tree.
Active Harness adapters, `cmux_agent_support.py`, surface/workspace lifecycle,
and `task_sessions.py` remain the owners of their existing boundaries.

## Manual vault repair

A blocked Stop now points to `$llm-obsidian:vault-repair` in Codex or
`/vault-repair` in Claude Code and to `.vault-meta/stop-hook-last.log`. The
skill performs one bounded local recovery/validation/Stop pass through the
existing writer and commit owner. It has no network, stash, reset, broad
staging, ownership bypass, or model loop. Its result reports either the exact
new commit SHA or the explicit `no-change` outcome.

## Release boundary

The authoritative full gate is an owner-controlled immutable receipt bound to
the clean exact candidate. It includes a bounded secret scan over added lines
and newly tracked secret-container paths relative to the nearest release tag.
The subsequent Harness review is confirmatory and must inspect that same HEAD;
any product edit invalidates both. Deferred runtime capabilities, accepted
governance deviations, and non-goals remain typed in the
[`RC2 defect ledger`](../acceptance/v2.6.6-rc2-defect-ledger.json).
The exact deviations are separately recorded in
[`RC2 accepted deviations`](../acceptance/v2.6.6-rc2-accepted-deviations.json).

This checkout prepares the handoff only. It does not push, tag, publish,
install, or merge the candidate.
