# LLM Obsidian v2.6.7 RC6.6

RC6.6 is a narrow engineering/fix request-publication candidate over exact
RC6.5 base `837b9319b5907cae3e985eac489dae6000fb6860`. It changes no phase
schema, order, retry budget, verification or review policy, dashboard behavior,
event wake behavior, or lifecycle authority.

## Canonical phase requests

- One workflow-owned constructor now emits every initial and continued
  engineering/fix request. Dispatch and the runtime worker no longer own
  separate pointer grammars.
- Initial reproduce iteration 0 and runtime continuation use
  `.task-pipeline/results/pass-0/reproduce.json` and
  `.task-pipeline/outputs/pass-0/reproduce.md`. Later initial-pass and retry
  requests use the same `pass-{iteration}` mapping.
- Pre-launch and continuation still use the existing shared contract
  publisher, which binds the same immutable owner-only template sidecar before
  exposing the request.

## Exactly-once adoption and restart safety

- If a non-template phase result already exists when the worker observes the
  canonical request, the worker withholds a duplicate phase notification while
  the existing two-read submit path validates and adopts it through code.
  Missing or untouched templates retain the ordinary same-session prompt.
- A production-shaped persistent-session regression prepublishes the initial
  reproduce request, template, output, and result; accepts one reproduce
  callback and receipt; advances once to root-cause; restarts the provider
  after acceptance; and completes the remaining phases without processing or
  prompting reproduce again.
- The strict submit matrix continues to reject pointer escape, request or
  callback identity drift, invalid template bindings, digest drift, symlinked
  evidence, and invalid result semantics. No provider or callback replay,
  compatibility reader, or old-run migration was added.

## Evidence and candidate boundary

The candidate gates cover initial dispatch, the production-shaped
engineering/fix traversal, callback submission, restart and retry behavior,
task-summary finalization, full Harness, code quality, instruction and routing
contracts, repository task/Outcome Contract validation, and direct diff audit.
The complete `make test` run reached the live-vault schema gate after those
checks and exposed two unresolved local-plan wikilinks already present in the
exact base `wiki/log.md`. RC6.6 leaves that independent baseline defect
untouched; the focused and configured candidate gates are green.

This candidate's Outcome Contract remains partially achieved because the
post-install engineering/fix smoke is deliberately deferred. After coordinator
merge and plugin refresh, one fresh cheap corridor must still prove all four
phases, verification, typed summary, reap, and empty owned resources without
manual resume or repeated provider effect. RC6.6 does not merge, push, tag,
publish, update plugins, run that smoke, or promote `v2.6.7`.
