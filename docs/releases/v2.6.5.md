# LLM Obsidian v2.6.5

Version 2.6.5 is a minimum-stabilization release. It introduces the exact-HEAD
attempt, typed provider-event, five-cycle finalization, and governed Split
contracts and activates the tested Split path after a separately proven
Stability Gate. Independent review found that several legacy/recovery paths do
not yet use those contracts end to end; the accepted residual scope is recorded
in `v2.6.5-accepted-review-waiver.md` and planned for 2.6.6. This release does
not add a scheduler or make merge/release an automatic Split effect.

## Exact-HEAD lifecycle

The new `ReviewAttempt` path owns one exact product HEAD and ends terminally at
approval, rejection, changes requested, attention, failure or cancellation.
Legacy V3/pre-activation continuation and the bounded rearm compatibility path
remain accepted debt; they are not evidence that historical provider
continuity has been fully removed.

Join also adds immutable `VerificationAttempt` identity:
`parent + verification profile + exact HEAD + attempt index`. A typed
coordinator mechanism-flake decision may create attempt 1 on the same HEAD,
without an empty commit or model/provider call. Attempt 0 remains durable; a
second retry or any decision/identity drift stops at attention. A changed HEAD
continues through the distinct fix-and-resubmit path.

## Typed provider events and bounded finalization

The new provider observation layer normalizes a closed `ProviderEvent` vocabulary
with exact provider, operation, run, generation and cursor identity. Delivery
receipts are irreversible. Legacy screen/time recovery authority remains in
the compatibility worker and is deferred to 2.6.6; typed events are therefore
not yet the sole production transition authority.

Interactive Codex delivery is now a single content-addressed pointer to the
complete immutable prompt artifact. This keeps the editor compact while the
artifact digest preserves the semantic input identity; initial delivery and
same-session continuation use the same policy. Claude still receives the full
interactive prompt. If Codex offers a native self-update, the harness selects
`Skip` for that launch only and never installs or suppresses future reminders.
Current-checkout callback notifications also preserve the original
purpose/boundary invocation without the incompatible legacy `current --plan`
argument, so a ready callback can be ingested without a second reviewer call.

For unknown adapter or runtime mechanics, the `tdd` workflow now starts with a
disposable live `prototype` while production remains unchanged. Only the
observed mechanism may be promoted into a real-seam RED regression, focused
GREEN integration evidence, and then one broad gate.

The manual transport smoke also has an opt-in model-free CMUX probe. It creates
one isolated workspace, an extra tab, right and left splits, verifies their
exact tree placement, closes only those surfaces, and proves the workspace
leaves no tail. This keeps UI transport experiments cheap without introducing
another lifecycle owner.

Claude print and Codex exec ephemeral adapters share one conformance contract:
fixed argument compilation, subscription preflight, schema validation,
capability checks and durable receipts. An adapter failure cannot silently
switch providers, paid access or hidden interactive mode.

These adapters are contract- and conformance-ready in 2.6.5. Production bounded
review still uses the interactive workspace launcher; wiring the frozen
execution profile to the adapter registry is explicit 2.6.6 work.

Finalization reserves one of five immutable cycles atomically. The policy can
compile a freshness-bounded independent route, but production reservation does
not yet supply that availability evidence, so the late independent route is
not claimed as live in 2.6.5. The optional policy remains additive to
PipelineSpec.

## Governed Split activation

`$split` still produces a canonical zero-effect manifest preview. Only the
explicit `$split --dispatch` branch may activate an approved plan. Each child
is bound to disjoint owned files and evidence, dependencies, an existing
workspace dispatch request, a registered pipeline/route and frozen time/token
ceilings.

`split-runner.py` validates with zero effects, then calls the existing dispatch
adapter for at most one dependency-ready bounded wave. Immutable launch
receipts make restart idempotent. Later waves require exact approved
resource-free terminal receipts. Attention, failure, cancellation, conflict,
budget drift, stale HEAD or open resources stops the graph before another
child/provider effect.

Join is deterministic and resource-free: original launch receipts, terminal
receipts and current child HEADs yield one manifest-order integration list. It
does not merge, push, tag, publish or release.

The current ownership projector still compares against the recorded base ref;
sealing an exact base commit before launch is accepted 2.6.6 debt.

Recovery remains effect-exact. Dispatch log context links bind the exact
context-path stem to their display title. The strict repair planner may accept
one typed exact binding, but rejects path, target, source or hash drift. A
durable reap completion receipt can settle only its matching pending
`reap-finalize` effect; replay, reuse and cross-task identity fail closed.

## Release evidence

The four component heads were adopted in A-B-C-D order without squashing or
rewriting their review evidence. A and D had durable product evidence but ended
in contained lifecycle attention; their providers were not replayed. Stability
Gate S passed at exact clean pre-activation HEAD
`023f69320b0833f8aac33a69f03d387ea2e485c1` before Split was enabled.

The qualified E1-E14 evidence map is in
[`v2.6.5-plan-success-evidence-map.md`](../acceptance/v2.6.5-plan-success-evidence-map.md).
Final gates, the bounded single-model dogfood, provider availability
disposition and clean resource inventory are specified in
[`v2.6.5-release-readiness.md`](../acceptance/v2.6.5-release-readiness.md).
The exact live request, child, callback, recovery and zero-effect Join are in
[`v2.6.5-live-split-dogfood.md`](../acceptance/v2.6.5-live-split-dogfood.md).

The technical release gate is green. Terminal implementation/release approval
is explicitly waived by the user for this minimum release; all 16 independent
findings are retained in the waiver and 2.6.6 plan rather than represented as
fixed.
