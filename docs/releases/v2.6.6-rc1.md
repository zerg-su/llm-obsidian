# LLM Obsidian v2.6.6 RC1

This release candidate removes the compatibility lifecycle that remained after
2.6.5 and narrows review authority to exact attempts, typed provider events and
exact Split ancestry. It is intentionally deletion-first: the branch removes
20,895 lines overall while adding bounded regressions and immutable evidence.

## Lifecycle authority

- A terminal review attempt is authoritative only for its exact product HEAD.
  Changed HEADs reserve a fresh bounded attempt; historical attempts are
  inspect/archive/cleanup-only.
- Human incident UUIDs, local paths, digests and decision prose no longer
  compile into executable recovery authority. Cross-HEAD rearm, drift,
  mechanism-recovery and post-fresh compatibility modules are removed.
- Reviewer liveness is observational. Time, stable screen state and
  dead/unknown process status cannot send input, submit a callback or restart a
  provider. Only the exact typed provider-event sequence can authorize the one
  submit effect.
- Bounded review diff packets truncate UTF-8 safely at byte boundaries.

## Split identity

Dispatch resolves an immutable base commit before creating a child worktree.
The SHA is persisted through task metadata, Split policy, manifest, launch and
terminal receipts, evidence projection and deterministic Join. Moving or
deleting the diagnostic branch cannot alter ownership; unrelated history is
rejected by ancestry proof.

## Evidence and candidate ceiling

Slices A-G have exact RED/GREEN/focused receipts. Integration binds named
exact-attempt, provider-event and Split-base traces, the audit manifest,
coverage floors and terminal dogfood evidence. The first release candidate
found two unobserved zero-caller adapters; the single allowed repair deleted
them without lowering coverage. The replacement exact candidate passed the
complete immutable gate.

Detailed E1-E8 proof and candidate identities are in
[`v2.6.6-rc1-release-readiness.md`](../acceptance/v2.6.6-rc1-release-readiness.md).
The required bounded review and final reap remain harness-owned. This task does
not push, tag, publish, deploy or release the candidate.
