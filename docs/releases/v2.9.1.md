# LLM Obsidian v2.9.1

Prepared locally on 2026-10-03. Publication is performed by the coordinator.

This candidate includes the combined Plan U work described in
[v2.9.0 preparation](v2.9.0.md), plus three startup corrections:

- Registered interactive Codex children set the supported
  `CODEX_TUI_DISABLE_KEYBOARD_ENHANCEMENT=1` fallback. Installed cmux 0.64.25
  loses synthetic letter keys in enhanced keyboard mode; legacy mode restores
  the owned Ctrl+G handoff without changing global configuration, authentication,
  model routing, or Claude behavior.
- Initial Codex input waits for a stable configured composer with its numeric
  context footer. The provisional startup field cannot trigger the first editor
  handoff; full-buffer identity still provides the submission authority.
- Failure to confirm initial input preserves the immutable published process,
  supervisor and provider generation. Typed exit/operation failure is separate,
  so exact cleanup retains its original authority.

The complete logical buffer remains the sole authority for Codex submission:
missing, stale or foreign observations cannot authorize Enter. The helper
returns an unsuccessful editor exit to preserve trailing whitespace. Codex may
show an editor error for this observation; it does not represent model input.

Claude and generated Codex marketplace metadata declare the same 2.9.1 version.
The implementation does not add modules, increase code-quality limits or expand
runtime permissions.

## Acceptance profile

The user authorized focused regression/package checks, one advisory Light Review
and one genuine Codex lifecycle on the final clean commit. Claude-dependent
cells remain explicit SKIP because Claude authentication is unavailable. Full
suite, full mutation rerun, native schema sampling and approval-capable Lifecycle
Review are waived in this expedited profile. Historical approvals and GREEN
reports apply only to their original commits.

A native no-submission prototype independently checks the editor hash/byte count
for empty and multiline drafts with literal whitespace. It is capability evidence,
not a substitute for the final provider-backed lifecycle. Publication readiness
requires fresh initial callback, continuation and cleanup evidence on the exact
candidate. The standard product four-cell release validator is unchanged;
the authorized exception belongs only to the coordinator's publication packet.
