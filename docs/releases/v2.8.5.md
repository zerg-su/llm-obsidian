# LLM Obsidian v2.8.5

Version 2.8.5 repairs Codex initial-input delivery when the native trust dialog
is painted after an apparently idle editor frame. It is a patch release;
pipeline contracts, budgets, and model-facing skill interfaces are unchanged.

## Stable Codex initial delivery

- A footerless transient numbered trust choice is no longer classified as an
  idle Codex editor.
- Before the first prompt is delivered, the native editor must remain idle for
  ten consecutive bounded observations. An interactive or unknown frame resets
  that stability window.
- The existing one-shot prompt and bounded second-Enter recovery remain
  unchanged; the repair grants no additional prompt replay authority.

## Evidence

- A disposable prototype localized the failure to the transition from the
  native trust choice into the real Codex editor.
- The regression covers both observed orderings: a visible trust dialog losing
  its footer during repaint, and an idle frame followed by a delayed dialog.
- Runtime-session, continuation-delivery, scope-ratchet, and complete repository
  tests pass on the exact candidate.
- A live Simple Sol Low review traversed the repaired initial-input path and
  approved the exact clean candidate with no findings.
