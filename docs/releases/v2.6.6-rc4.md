# LLM Obsidian v2.6.6 RC4

RC4 is the deterministic review-control-plane candidate over released RC3
commit `7033413afc9dc7666f4a2a76de33c088dbfcbfef`. It keeps the existing Harness,
FSM, providers, pipeline DSL, and permission boundaries. It adds no scheduler,
provider fallback, hidden model call, or second orchestration layer.

## Deterministic review lifecycle

- Validation, frozen task metadata, finalization, and runtime launch now bind
  one canonical effective-review-topology value and digest.
- Exact accepted callbacks advance incrementally and exactly once through
  aggregation, finding delivery, executor continuation, and cleanup, including
  restart after every durable prefix.
- Exact release evidence binds the plan, Outcome Contract, reviewed artifact
  root, finding disposition, and candidate HEAD.
- Initial interactive input is accepted only after semantic provider activity;
  transport success and rate-limit repainting are not completion evidence.

## Measured completeness and engineering quality

- The RC4 transition certificate derives the supported denominator from the
  production lifecycle and proves 50/50 supported edges, 16/16 curated
  forbidden edges, 106/106 closure pairs, and eight bounded witnesses.
- Holistic and engineering prompts use one six-part review denominator:
  Quality, Implementation, Testing, Simplification, Documentation, and
  Security. Intent-only review remains outcome-scoped.
- Skill and instruction changes are mutation-tested against byte budgets,
  routing, cross-surface parity, and four hermetic pressure scenarios.

The executable evidence map and fish-compatible handoff commands are in
[`v2.6.6-rc4-release-readiness.md`](../acceptance/v2.6.6-rc4-release-readiness.md).

## Release boundary

This checkout prepares a local verified candidate only. It does not push, tag,
publish, install, or merge. Publication remains a user action after the clean
exact-HEAD gate and the configured single holistic Opus release review approve
the same candidate bytes.
