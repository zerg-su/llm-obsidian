# LLM Obsidian v2.8.4

Version 2.8.4 repairs the initial custom-step delivery failure exposed by the
mirrored 2.8.3 dogfood runs. It is a patch release; pipeline contracts,
budgets, and model-facing skill interfaces are unchanged.

## Custom initial delivery

- The first custom step is published before its provider session is launched.
  While that initial callback is pending, the runtime now waits for the
  launch-owned delivery instead of sending the same request through retained
  notification transport a second time.
- After the first durable receipt, successor model steps retain their existing
  one-shot notification path.
- An already-published custom-step callback continues to outrank notification
  recovery and advances without provider replay.

## Evidence

- A disposable RED prototype reproduced the live failure as one attempted
  duplicate initial notification and `callback-invalid` attention.
- The production regression covers both supported races: an early callback and
  a pending callback owned by the already-launched provider. Both converge with
  zero initial notification attempts and exactly one successor notification.
- Focused custom, dispatch, crash-matrix, sequence, and submit-boundary tests
  pass.
- The complete repository test gate and a Simple Sol review pass on the exact
  candidate.
