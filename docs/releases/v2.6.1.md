# LLM Obsidian v2.6.1

Version 2.6.1 completes independent review topology without adding another
scheduler, store, state machine, or pipeline engine.

## Review topology

- Simple: one selected holistic reviewer.
- Deep default: independent Anthropic and OpenAI holistic reviewers.
- Deep single-model: intent and engineering sessions on the selected model.
- Full: an explicit-only four-lane provider/responsibility grid. It is never
  selected by defaults, heuristics, task metadata, or risk policy.

Public lane IDs are provider-stable (`anthropic-*`, `openai-*`). Model-family
names remain centralized routing aliases and can change without rewriting
durable review identity.

## Isolation and recovery

Each reviewer can read the exact ContextPacket, plan, wiki evidence, and product
checkout, but can write only its own callback input and ephemeral test scratch.
Sibling callbacks and product/Git paths remain read-only for Claude and Codex.

The release also closes lifecycle defects exposed by Full dogfood: fresh
selector reuse, checkpoint hydration, bounded multi-part fix deltas, partial
continuation replay, accepted-callback cleanup, and exact exited-parent
identity. A terminal accepted callback can be consumed without a resume
checkpoint; verification continuation still requires one and fails closed.

## Compatibility

The review-v1 axis vocabulary and public lane IDs changed intentionally. Finish
or cancel active 2.6.0 reviews before upgrade. Existing active review evidence
is not migrated or reinterpreted.

## Upgrade from 2.6.0

```bash
python3 scripts/upgrade-preflight.py --root .
git pull --ff-only
python3 scripts/codex-adapter.py --apply
scripts/mcp-gateway/mcp-gateway.sh codex-sync --apply
python3 scripts/harness-cli.py doctor
```

Start a new Claude/Codex session after reinstalling the adapters.

## Release gate

```bash
make test
make acceptance-check
python3 scripts/validate-vault.py --summary
python3 scripts/codex-adapter.py --check
scripts/mcp-gateway/mcp-gateway.sh codex-sync --check
references/upstream-skills/verify_snapshots.py
git diff --check
```

The exact release HEAD additionally requires one bounded explicit Full live
smoke and one final independent Opus review.

## Maintainer release commands

Run only after the exact release HEAD is clean and approved:

```fish
set RELEASE_SHA (git rev-parse HEAD)
test (count (git status --porcelain)) -eq 0

git push origin main
set REMOTE_SHA (git ls-remote origin refs/heads/main | string match -r '^[0-9a-f]+')
test "$REMOTE_SHA" = "$RELEASE_SHA"

git tag -a v2.6.1 $RELEASE_SHA -m "LLM Obsidian v2.6.1"
git push origin v2.6.1
git ls-remote --exit-code origin refs/tags/v2.6.1

gh release create v2.6.1 \
  --repo zerg-su/llm-obsidian \
  --title "LLM Obsidian v2.6.1" \
  --verify-tag \
  --notes-file docs/releases/v2.6.1.md
```
