# LLM Obsidian v2.6.7 RC6.5

RC6.5 is an event-first runtime wake and dashboard timing candidate over exact
RC6.4 product base `f00d8ed3ff7e53c3b11470709068116224617009`. It adds no
scheduler, shared daemon, lifecycle authority, callback/provider replay, model
polling, or generic attention recovery.

## Event-first wake boundary

- Each existing interactive runtime worker may own one optional, filtered
  `cmux events.v1` subscription with a private cursor. A closed parser accepts
  only exact session, notification, surface, workspace, reconnect, and cursor
  gap observations bound to that worker's durable identities.
- A matching observation is only a lossy hint to run the existing durable
  transport reconciler. Events never authorize state transitions, callback
  acceptance, provider input, replay, recovery, cleanup, or completion.
- Full transport reconciliation is event-first with a maximum 30-second
  `fallback-poll`. Every existing two-read artifact guard retains its short
  confirmation read. Prompt, checkpoint, provider-exit, callback, liveness,
  and guardian-control deadlines remain independent light duties.
- Missing capability, launch failure, malformed or oversized NDJSON, EOF, and
  ambiguous identity do not create attention. Degraded streams reconcile once
  and retry with backoff; unavailable streams continue through deadlines and
  fallback polling.

## Observability and timing

- Runtime roots atomically retain only the latest full-reconcile wake and
  latest progressing wake. Diagnostics expose bounded owner, operation, run,
  generation, source, closed event name/sequence, timestamp, and
  progressed/no-change outcome. Raw payloads, prompts, output, notification
  bodies, and screens are never persisted.
- The root-owned `TDD slices` dashboard step now freezes as
  `duration`/`complete` at accepted terminal timing or the earliest validated
  liveness start of an exact later-step child. Invalid, reversed, future,
  stale-revision, or non-current-run evidence renders time unavailable.
  Dashboard layout, order, expansion, and non-timing labels are unchanged.

## Evidence and candidate boundary

Hermetic adapter, runtime-session, diagnostics, crash/restart, lifecycle
simulator, and dashboard matrices cover strict routing, event-before-fallback,
stable confirmation, independent deadlines, source degradation, atomic wake
receipts, and frozen step timing. The candidate gates include the focused
suites, full Harness and Harness coverage, code-quality and instruction
contracts, repository task/Outcome Contract validation, and a direct audit
against `config/code-quality-baseline.json`.

This candidate's Outcome Contract is partially achieved because it does not
establish post-install dogfood. After coordinator merge and plugin update, a
fresh host session must still run the separate built-in and custom release
corridors and prove progressing cmux-event receipts, correct frozen timing,
typed reap, and empty owned resources.
RC6.5 does not merge, push, tag, publish, update the installed RC6.4 plugin, or
promote `v2.6.7`.
