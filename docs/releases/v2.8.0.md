# LLM Obsidian v2.8.0

Version 2.8.0 adds Architecture Workflow v1: two new carriers that turn
architectural intent into accepted project knowledge and then into an executable
Work Item DAG, under one shared artifact contract. It does not add a scheduler,
a runtime or store owner, provider fallback, retry budget, migration path, or
runtime delivery state in the vault. `clarify`, `research`, `prototype`, `design`
and `review` stay reusable primitives; nothing about the existing dispatch,
review, or reap lifecycle changes.

The governing invariant across every new boundary: downstream artifacts may
discover upstream problems, but may not silently resolve them. They return the
problem to its owning stage as a canonical Upstream Gap.

## Architecture and decompose carriers

- `architecture` owns the Design Frontier and whole-system knowledge: vision,
  architecture, bounded design, spec and contract artifacts, each with its own
  role rather than one generic kind. It orchestrates one explicit handoff to a
  carrier and collects the returned artifact into project context.
- `decompose` owns delivery decomposition and the Planning Frontier. It maps a
  `<Project> Work Graph` and its Work Items, proves bidirectional traceability
  against accepted intent, and derives waves from `depends_on` plus real
  concurrency constraints. There is no stored parallel-safety relation.
- Both carriers run MAP → ACCEPT → MATERIALIZE. MAP and ACCEPT are read-only and
  conversational, with zero writes and zero address effects; MATERIALIZE needs a
  separate explicit write authorization and goes through one bounded
  `vault-write.py` transaction.
- `implementation-plan` gains a Work Item input path that verifies per-class
  authority (project artifacts accepted, decisions active or accepted, never
  superseded), total and current pins, and recovery/projection consistency
  before any file or TDD planning.

## Shared artifact contract and path safety

- `docs/skill-references/architecture-artifacts.md` is the single contract both
  carriers read completely: roles, canonical placement under
  `wiki/projects/<project>/`, identity as the globally unique title plus the
  DragonScale address, revisions, report-only freshness, and lifecycle.
- `scripts/architecture_paths.py` owns the grammar, the vault-wide collision key
  `NFC(title).casefold()` checked against the complete link namespace including
  aliases, role-to-folder mapping, and containment. Symlinks are rejected on
  every component from the wiki root through the selected role directory, and
  the resolved destination must equal the canonical lexical destination, so
  neither a project-root nor an in-project role redirect can move an accepted
  artifact into another project.
- Generic `wiki/` confinement in the writer is not the project boundary: a path
  such as `wiki/projects/alpha/../beta` stays unacceptable.

## Behavioral evidence machinery

- `scripts/architecture_workflow_pressure.py` and
  `scripts/architecture_workflow_audit.py` are release-owned. The frozen legacy
  eval framework keeps its own bytes; nothing about the RC4 denominator was
  rebuilt or migrated.
- Every behavioral record binds the child provider session identity that
  answered the case, required unique across the corpus, plus the executing
  coordinator session. Records and transcripts are both credential-sanitized on
  the complete canonical record, and publication fails closed rather than
  silently rewriting.

## Repository fixes this release carries

- The bounded review resolution fix delta excludes committed
  `docs/acceptance/evidence/` bytes through one registered git command, so
  acceptance evidence can no longer crowd a small product fix out of the 1 MiB
  transport cap.
- The frozen RC4 governing-source projection canonicalizes the `CLAUDE.md`
  skill catalogue line, so shipping a new skill no longer invalidates a
  historical denominator, while any other drift still fails closed.
- The release-version gate derives the current version from the packaged build
  instead of a hard-pinned constant.

## Acceptance

- All nineteen A-S pressure cases and all eleven read-only dogfood cases pass at
  the frozen behavioral subject `884066a4`, executed with one fresh child session
  per case: thirty distinct child identities under one coordinator session.
- Three green full-suite runs: the task's authorized unchanged-HEAD retry and the
  independent coordinator run at the tested evidence parent, plus a coordinator
  run at the exact release candidate tip. Receipts are recorded under
  `docs/acceptance/evidence/architecture-workflow-v1/`, with the coordinator side
  under its `coordinator/` subdirectory.
- The dispatch finalization lineage used all five cycles and ended exhausted;
  every cycle found real defects and every finding was applied. Terminal
  acceptance is coordinator-owned through standalone deep reviews, where both
  Fable lanes approved. The single Sol item, an independent receipt bound to the
  exact release HEAD, is satisfied out of tree and unsatisfiable within it,
  because committing such a receipt moves the tip it attests.
