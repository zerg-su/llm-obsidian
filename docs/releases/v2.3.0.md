# LLM Obsidian v2.3.0

Version 2.3.0 moves the visible Claude Code/Codex CLI lifecycle behind one
restartable, code-owned harness. Skills now describe intent and reasoning;
typed modules own worktrees, cmux, provider processes, callbacks, verification,
recovery, and exact cleanup.

## Highlights

- Owner-scoped operation ledger with write-ahead effects and restart-safe
  `status`, `inspect`, `resume`, `reconcile`, `cancel`, `close`, and `doctor`.
- Unified `review`: one same-model holistic lane by default, independent axes
  in deep mode, and explicit cross-model routing with registered aliases.
- The same state-driven review command covers dispatched tasks and the current
  checkout. Current-checkout review needs no `.task-meta.json` and keeps its
  ContextPacket and callbacks in owner-only scratch outside the checkout.
- Review evidence becomes final only after bounded provider exit and exact
  reviewer cleanup; retryable ownership and orphan termination are re-probed
  without approving a leaked surface, and blocked deep axes remain durable
  attention.
- Live reviewer deadlines become durable `callback-timeout` attention, and a
  late callback loses atomically to that deadline. Early provider exit remains
  supervised, and neither normal nor deep resolution can convert the timed-out
  gate into approval without explicit recovery.
- Protected `research`: minimal context, vaultless network fetch, networkless
  synthesis, cited typed result, and a coordinator-owned vault transaction.
- Five engineering workflows: `debug`, `tdd`, `design`, `prototype`, and
  `resolve-conflict`.
- Four release cells on one exact clean SHA instead of the historical 60-cell
  skill-by-runtime matrix.

## Clean-cut changes

The public skills `dispatch-workspace`, `review-dispatch`, `review-send`,
`reap-send`, and `autoresearch` are removed without aliases. Use `dispatch`,
`review`, `reap`, and `research`. Reviewer and task-side typed delivery is now
internal harness transport.

Version 2.3.0 is the clean runtime baseline. It does not ship legacy aliases,
dual engines, or state converters for pre-harness task, review, or research
operations. Historical pages and archived reviews remain ordinary vault data
and are not rewritten.

## Clean install

```bash
git clone --branch v2.3.0 https://github.com/zerg-su/llm-obsidian.git
cd llm-obsidian
bash bin/setup-clean-machine.sh

python3 scripts/codex-adapter.py --check
scripts/mcp-gateway/mcp-gateway.sh codex-sync --check
python3 scripts/harness-cli.py doctor
```

Install the local marketplace/plugin through the Claude Code plugin UI. For
Codex:

```bash
codex plugin marketplace add "$(pwd)"
codex plugin add llm-obsidian@llm-obsidian-codex
```

Start a new Claude/Codex thread after installation so the host loads the 2.3.0
skill registry.

## Existing development vaults

The supported installation path is a clean 2.3.0 checkout. Maintainers carrying
an earlier development vault should back up the vault, finish or cancel live
operations with the old checkout, install 2.3.0 cleanly, and then copy only
their vault content. Pre-harness runtime state and generated indexes are not
adopted.

## Verification

The model-free release checks are:

```bash
make test
make acceptance-check
python3 scripts/validate-vault.py --summary
python3 scripts/codex-adapter.py --check
scripts/mcp-gateway/mcp-gateway.sh codex-sync --check
git diff --check
```

`make acceptance-live` is the maintainer-only provider gate. It runs or resumes
exactly four cells through the repo-owned in-process driver. Global preflight
runs before the first external effect and is retained with the exact route
capabilities in the schema-v3 report. A classified failure resumes only its
failed cell, preserving prior green evidence. Publication must wait for four
schema-v2 cell passes, an empty failure list, and the matching preflight
artifact in one schema-v3 report on the exact release SHA.

## Rollback

First finish or cancel all 2.3.0 operations and verify a clean worktree. Runtime
state is not backward-compatible; rollback means restoring a backup or using a
fresh checkout of the previous tag.

```bash
git switch --detach v2.1.3
```

## Maintainer publication

These commands are preparation only. Run them only after explicit publication
authorization, a clean release commit, a full hermetic pass, four live cells,
and final review on the same SHA:

```bash
RELEASE_SHA="$(git rev-parse HEAD)"
test -z "$(git status --porcelain)"

git push origin main
test "$(git ls-remote origin refs/heads/main | awk '{print $1}')" = "$RELEASE_SHA"

git tag -a v2.3.0 "$RELEASE_SHA" -m "LLM Obsidian v2.3.0"
git push origin v2.3.0
git ls-remote --exit-code origin refs/tags/v2.3.0

gh release create v2.3.0 \
  --repo zerg-su/llm-obsidian \
  --verify-tag \
  --notes-file docs/releases/v2.3.0.md
```

The release command deliberately omits `--target`: the already-pushed annotated
tag is authoritative, avoiding a GitHub `target_commitish` mismatch.
