# LLM Obsidian v2.5.1

Version 2.5.1 stabilizes the 2.5 harness against nine real repository tasks.
It does not introduce a second controller or change the model-authored pipeline
boundary; it makes the existing lifecycle more exact and recoverable.

## Highlights

- Exact surface ownership is recorded before provider start, and abnormal
  acceptance exits release only the surfaces they own.
- Stale operations are classified against terminal state and exact registry,
  process, worktree, and surface identities before any recovery advice.
- Review phases carry prior accepted evidence, validate callbacks explicitly,
  bound summaries and telemetry claims, and cannot finalize before resolution.
- Reap rejects ambiguous mode requests and retains shared plans.
- Task prompts render the canonical final Wiki Summary contract.
- Vault navigation and the pinned Superpowers/Matt Pocock comparison were
  refreshed without importing repository-specific issue, PR, or installer
  mechanics.

## Protected research repair

Three real protected-research attempts exposed successive launch defects.
Version 2.5.1 now:

1. turns a nonzero provider exit into immediate typed attention instead of
   waiting for a callback that cannot arrive;
2. resolves and persists the absolute interpreter before the protected worker
   sanitizes `PATH`;
3. bypasses cmux's provider wrapper only for `research-fetch` and
   `research-synth`, invoking the pinned provider directly under the isolated
   environment.

Ordinary dispatch and review sessions retain their exact-surface cmux wrappers.
Focused regressions cover both sides of that boundary.

## Dogfood scope

RT01 through RT09 completed, were independently reviewed, and were integrated.
They cover stale reconciliation, exact cmux cleanup, same-session review delta,
invalid callback handling, auto-close ownership, runtime-neutral telemetry,
stale identity diagnosis, protected upstream research, and vault health.

RT08's upstream comparison is deliberately pinned-only: the outbound research
attempts failed before the final launcher repair, so the document does not claim
that current upstream drift was checked. RT10 is intentionally deferred until
the released 2.5.1 Claude/Codex adapters are installed and a new agent session
loads them; it is post-release dogfood, not fabricated release evidence.

## Clean install

```bash
git clone --branch v2.5.1 https://github.com/zerg-su/llm-obsidian.git
cd llm-obsidian
bash bin/setup-clean-machine.sh

python3 scripts/codex-adapter.py --check
scripts/mcp-gateway/mcp-gateway.sh codex-sync --check
python3 scripts/harness-cli.py doctor
```

For Codex, install the local marketplace/plugin and start a new thread:

```bash
codex plugin marketplace add "$(pwd)"
codex plugin add llm-obsidian@llm-obsidian-codex
```

## Upgrade from 2.5.0

Finish or cancel active task, review, research, and reap operations first:

```bash
python3 scripts/upgrade-preflight.py --root .
git pull --ff-only
python3 scripts/codex-adapter.py --apply
scripts/mcp-gateway/mcp-gateway.sh codex-sync --apply
python3 scripts/harness-cli.py doctor
```

Start a new Claude/Codex thread after reinstalling the adapters.

## Maintainer release commands

Run only after the final review and release checks are green:

```fish
set RELEASE_SHA (git rev-parse HEAD)
test (count (git status --porcelain)) -eq 0

git push origin main
set REMOTE_SHA (git ls-remote origin refs/heads/main | string match -r '^[0-9a-f]+')
test "$REMOTE_SHA" = "$RELEASE_SHA"

git tag -a v2.5.1 $RELEASE_SHA -m "LLM Obsidian v2.5.1"
git push origin v2.5.1
git ls-remote --exit-code origin refs/tags/v2.5.1

gh release create v2.5.1 \
  --repo zerg-su/llm-obsidian \
  --title "LLM Obsidian v2.5.1" \
  --verify-tag \
  --notes-file docs/releases/v2.5.1.md
```
