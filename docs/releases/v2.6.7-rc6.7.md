# LLM Obsidian v2.6.7 RC6.7

RC6.7 adds durable, display-only engineering/fix phase timing and a
policy-valid custom-start corridor over RC6.6. It does not add lifecycle,
recovery, callback, provider, or cleanup authority.

## Phase timing

- Request publication may write `pipeline-fix/timing/pass-N/<step>/start.json`.
  Accepted callbacks may write the matching receipt-bound `completion.json`.
- Both files bind owner, parent operation, child operation/run, step, and
  iteration. The dashboard accepts only the exact matching pair and renders an
  active elapsed interval or an accepted frozen duration.
- Missing, partial, malformed, symlinked, drifted, reversed, or future files
  make time unavailable only. They never prevent the existing publication,
  acceptance, event, or cleanup path. On retries, the newest active pass wins
  over an older completed pass.

## Policy-valid custom start

A pending owner-only validation snapshot can start without a dialog or token
when its exact request bytes, coordinator identity, approved plan, compiled
definition, approval card, prompt, route, review, and session all revalidate.
The snapshot is consumed atomically before effects. Existing explicit host
approvals still accept their exact one-shot token; reject, revise, consumed, or
drifted records fail closed.

## Candidate boundary

The scripts ratchet is 287 Python files / 107,600 lines for this bounded
candidate. RC6.7 does not merge, push, tag, publish, update plugins, run
post-install dogfood, or promote the final release.
