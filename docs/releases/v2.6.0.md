# LLM Obsidian v2.6.0

Version 2.6.0 makes the approved user outcome a first-class, bounded input of
the existing harness-first lifecycle. It does not introduce another scheduler,
pipeline engine, goal authority, or model-owned transition.

## Highlights

- One canonical Outcome Contract lives inside the approved plan and receives a
  stable digest independent of editorial plan changes.
- New task metadata v4 binds that digest beside the approved plan identity;
  built-in and custom semantic steps receive the same outcome through existing
  ContextPacket pointers.
- Review evaluates the outcome before implementation mechanics, classifies all
  declared evidence, checks non-goals, and requires typed dispositions for
  every material finding.
- Wiki Summary v2 records `achieved`, `partially-achieved`, or `not-achieved`
  with declared evidence IDs and durable residual-gap pointers.
- The engineering skills were tightened with the applicable general practices
  from pinned Superpowers and Matt Pocock Skills references, then checked by a
  five-pass goal-preservation audit and frozen paired evaluations.

## Outcome-preserving flow

```text
clarify → design/save-plan → dispatch → semantic pipeline → review → reap
   contract created        digest bound       evidence judged   disposition
```

The harness continues to own identities, limits, transitions, effects,
verification, cleanup, and callback transport. Models decide only the semantic
work inside those boundaries. A green test, clean diff, accepted callback, or
task summary cannot substitute for the declared desired outcome.

## Review and recovery

- `review-inspect` gives locked-down reviewers bounded read-only access to the
  exact packet, worktree, refs, commits, and path-scoped diffs without general
  shell access.
- Simple review remains one holistic session. Deep review remains two
  independent lanes: Fable for specification/outcome and Sol for standards,
  correctness, architecture, and security.
- Applied, rejected, and out-of-scope material findings carry exact
  identity-bound evidence. Rejected findings require rationale; out-of-scope
  findings require both rationale and a durable follow-up.
- Accepted callback cleanup and interrupted finalization recover only through
  exact owned process, supervisor, surface, callback, and receipt identities.

## Skill intelligence

The release refines `clarify`, `design`, `prototype`, `save-plan`, `debug`,
`tdd`, `review`, and `reap`. The manual-only `improve-skills` gate now audits
invocation, information hierarchy, steering, pruning, and goal preservation.
It applies only demonstrated behavior-preserving fixes and keeps foreign GitHub,
tracker, installer, worktree, and orchestration mechanics out of the toolkit.

## Compatibility

New tasks use task metadata v4 and Wiki Summary v2. Historical v1-v3 operations
and v1 summaries remain readable under their frozen contracts; active old
operations must finish or be cancelled before upgrade and are never converted
in place.

## Clean install

```bash
git clone --branch v2.6.0 https://github.com/zerg-su/llm-obsidian.git
cd llm-obsidian
bash bin/setup-clean-machine.sh

python3 scripts/codex-adapter.py --check
scripts/mcp-gateway/mcp-gateway.sh codex-sync --check
python3 scripts/harness-cli.py doctor
```

For Codex, install the local marketplace/plugin and start a new thread:

```bash
codex plugin marketplace add "$(pwd)"
codex plugin add llm-obsidian@llm-obsidian-codex
```

## Upgrade from 2.5.1

Finish or cancel active dispatch, review, research, and reap operations first:

```bash
python3 scripts/upgrade-preflight.py --root .
git pull --ff-only
python3 scripts/codex-adapter.py --apply
scripts/mcp-gateway/mcp-gateway.sh codex-sync --apply
python3 scripts/harness-cli.py doctor
```

Reinstall the local adapters and start a new Claude/Codex session so the host
loads the 2.6 skill registry and hooks.

## Release gate

```bash
make test
make acceptance-check
python3 scripts/validate-vault.py --summary
python3 scripts/codex-adapter.py --check
scripts/mcp-gateway/mcp-gateway.sh codex-sync --check
references/upstream-skills/verify_snapshots.py
git diff --check
```

The exact clean release HEAD additionally requires the frozen paired comparison,
four real-task dogfood results, the negative semantic-drift smoke, bounded live
`review-inspect`, and one final deep Fable + Sol xhigh review.

## Maintainer release commands

Run only after the final review and release checks are green:

```fish
set RELEASE_SHA (git rev-parse HEAD)
test (count (git status --porcelain)) -eq 0

git push origin main
set REMOTE_SHA (git ls-remote origin refs/heads/main | string match -r '^[0-9a-f]+')
test "$REMOTE_SHA" = "$RELEASE_SHA"

git tag -a v2.6.0 $RELEASE_SHA -m "LLM Obsidian v2.6.0"
git push origin v2.6.0
git ls-remote --exit-code origin refs/tags/v2.6.0

gh release create v2.6.0 \
  --repo zerg-su/llm-obsidian \
  --title "LLM Obsidian v2.6.0" \
  --verify-tag \
  --notes-file docs/releases/v2.6.0.md
```
