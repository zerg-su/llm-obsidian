# ADR: keep harness 2.3 as the pipeline engine

Status: superseded by [v2.4 state-free executable lifecycle](v2.4-state-free-executable-lifecycle.md)
Date: 2026-07-30  
Applies to: LLM Obsidian 2.4

## Context

The 2.4 specification required a net-value gate after shadowing lifecycle and
engineering profiles but before switching any production path. The proposed
composition layer added a compiler, registry, controller, receipt ledger, and
shadow helpers around the existing 2.3 operation supervisor and workflow
facades.

Fable reviewed product HEAD `5e9cb0b` and found that the controller introduced
a second operation identity without replacing the production dispatch identity.
Its executor port would therefore wrap the existing workflow or reimplement its
launch/effect/resource invariants.

## Decision

Harness 2.3 remains the only execution engine. LLM Obsidian 2.4 keeps a pure,
non-executable built-in catalog and compiler for stable semantic contracts:

- code-owned lifecycle, change, and fix descriptors;
- exact primitive-version and schema-chain validation;
- session-mode, skill, and capability validation;
- canonical definition hashing;
- a bounded renderer that explicitly says execution remains with harness 2.3.

`dispatch-runner.py validate` consumes the lifecycle entry and includes its
hash and rendered summary in the existing pre-approval preview. This is a
read-only consumer; `start` still enters the unchanged 2.3 workflow.

The experimental controller, receipt ledger, and shadow product modules are
removed. The catalog does not create `OperationSpec`, persist progress, launch
providers, claim runtime budgets, or claim sandbox enforcement.

## Net-value evidence

- `added_non_test_loc` at the gate: **1,364**
- honestly `deletable_non_test_loc`: **100–400**
- retained fallback non-test LOC after resolution: **466**

The required inequality `deletable_non_test_loc > added_non_test_loc` did not
hold. Production composition was therefore cancelled by design, not postponed.

## Consequences

- Existing dispatch, review, research, reap, replay, repair, and cmux behavior
  does not change.
- There is no second store, FSM, supervisor, operation identity, CLI, or
  telemetry path.
- Approval remains a pre-execution user/coordinator boundary, not a fake
  `human_gate` runtime primitive.
- `bounded_loop` is not advertised until it has a real bounded control contract.
- A future executable composition proposal must prove a single production
  operation identity and delete more orchestration than it adds before it can
  cross the same gate.

This decision rejected the second-controller implementation. It was later
superseded for the lifecycle slice after the user explicitly restored the full
2.4 functional goal and approved a different architecture that keeps the
existing operation identity and supervisor.

It still does not authorize model-authored custom pipelines from the 2.5 plan.
