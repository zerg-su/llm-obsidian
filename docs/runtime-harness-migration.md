# Runtime harness migration inventory

Version 2.3.0 is a clean cut from skill-owned terminal orchestration to one
restartable, code-owned harness. Skills retain intent, reasoning discipline,
authorization boundaries, and completion criteria. `scripts/harness/` owns
operation identity, model routing, context packets, worktrees, cmux, provider
processes, callbacks, verification, retries, reconciliation, and cleanup.

Direct `cmux`, `claude`, and `codex` process calls are confined to
`scripts/harness/adapters/`. Protected-research providers write only their typed
artifact; a code-owned watcher validates it, records the checkpoint, and routes
the bounded coordinator wake through the generic cmux adapter. Provider
sandboxes receive neither a generated terminal notifier nor the cmux socket.
Protected providers also receive a fixed stage-local environment instead of
the coordinator environment, and synthesis is bound to the advance-validated
fetch artifact by a content-free harness-state digest.
The machine-readable allowlist is empty, and
`scripts/runtime-harness-lint.py --strict` rejects any production exception.

The executable inventory is regenerated by
`python3 scripts/runtime-harness-lint.py --strict --json`. The release invariant
is `direct_callers: {}` and an empty temporary allowlist; adapter files are the
only place allowed to spell provider/cmux process effects. Retired
`cmux_agent_supervisor.py` remains as non-production migration evidence and is
explicitly outside the production inventory; no public route invokes it.

The 2.3.0 clean cut leaves no temporary direct-runtime exception.

The inventory contains paths and runtime binary names only. It never records
prompts, commands, callback bodies, screen content, or other user data.

## Public skill migration

There are no compatibility aliases for removed public skills:

| Before 2.3.0 | 2.3.0 public route |
|---|---|
| workspace-specific dispatch variant | `dispatch`; placement is harness policy |
| separate review dispatcher and reviewer sender | `review`; typed submission is internal transport |
| task-side reap sender | `reap`; Wiki Summary delivery is internal transport |
| autonomous protected-research skill | `research` |

The public workflow set is `dispatch`, `review`, `research`,
`unsafe-research`, and `reap`. Simple review is one same-model holistic lane by
default. Deep review keeps independent axes. Cross-model routing and registered
model-alias overrides are explicit. Protected `research` uses a minimal
ContextPacket, a vaultless networked fetch lane, a networkless synth lane, and a
coordinator-owned vault write. `unsafe-research` is an explicit single-context
escape hatch and never a fallback.

## Operation recovery

The owner-scoped ledger and write-ahead effect marker are authoritative after
an interruption:

```bash
python3 scripts/harness-cli.py status
python3 scripts/harness-cli.py doctor
python3 scripts/harness-cli.py inspect <operation-id>
python3 scripts/harness-cli.py reconcile
python3 scripts/harness-cli.py resume <operation-id>
```

Use `cancel` or `close` only for the exact operation after ownership is proven.
The harness never retries an uncertain model start, callback, send, or close
until reconciliation proves the prior effect. Unknown state remains visible as
`attention-required`.

## Upgrade boundary

Finish or cancel all operations with the installed version before replacing
files:

```bash
python3 scripts/upgrade-preflight.py
```

The command rejects active harness operations, unreaped worktrees, unfinished
legacy review/research runs, and non-archived broker tasks. It does not adopt
live 2.2.x state into the new engine. After the overlay, run the preflight
again, regenerate native Codex packaging, and start a new agent thread so the
host reloads the clean public skill registry. See
[v2.3.0 release notes](releases/v2.3.0.md) for exact install, upgrade, rollback,
and post-upgrade checks.
