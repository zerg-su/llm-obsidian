### Mechanism defects found (3 escalations, all coordinator-resolved)

Protected research fetch failed three times, always `exit_code` 127 with no artifact and no fetched sources. The coordinator repaired two layers (`794bdd0`, `177dc27`); the third root cause proved distinct and outside repository ownership, and the coordinator then authorized pinned-only delivery.

1. The runtime exited 127 while the operation stayed `awaiting-callback` indefinitely — no exit-code classification, `attempt_limit` never consumed. Repaired.
2. Env-shebang resolution read a PATH not guaranteed to hold the interpreter, and the resolved argv was never persisted, so the transform could not be confirmed from harness state. Repaired.
3. **Actual root cause.** The worker runs inside the cmux research surface, so `provider_argv` takes the cmux wrapper-shim branch and replaces `argv[0]` with a `#!/usr/bin/env bash` shim — which makes the pinned Node interpreter unreachable dead code on this path. The shim execs cmux's `cmux-codex-wrapper`, whose `find_real_codex()` scans `PATH` for `codex` and exits 127 at its line 242. `RESEARCH_PATH` is deliberately `/usr/bin:/bin:/usr/sbin:/sbin`. This is structural rather than environmental: the flow sanitizes PATH on purpose and the third-party wrapper requires the provider on PATH, so widening the PATH would weaken the isolation the flow exists to provide. Proven fix direction — the direct invocation under full sanitization returns 0 — is to skip the wrapper-shim branch for `research-fetch` and `research-synth`. Not applied here: it touches the shared launch path used by dispatch and review.
