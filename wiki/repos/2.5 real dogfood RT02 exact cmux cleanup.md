# 2.5 real dogfood RT02 exact cmux cleanup

# RT02 — exact cmux surface cleanup miss (backlog `cmux-acceptance-surface-cleanup`)

Reproduced, diagnosed, regression-covered and repaired the backlog miss where the live acceptance run abandoned its exactly-owned cmux surface. Three commits on `task/df250-real-rt02-cmux-cleanup`; final HEAD `46f9738`.

## Root cause

`runtime_sessions.start` binds one owned surface per operation before the provider launches, but release was wired **only** to the success path (`_await_cleanup`). The per-operation body of `live_acceptance_driver.run_cell` had no guard spanning `start` → `_await_cleanup`, so any raise in between abandoned a live surface. `execute_release` caught only `Exception`, so an operator interrupt (`BaseException`) also persisted no classification.

The deeper cause: the evidence contract already requires `owned_resources_remaining == 0`, but an abandoned operation never emits an evidence row, so that invariant was structurally unreachable on exactly the paths that violated it — enforced only where it could not fail.

## Three proven boundaries, one defect

| Boundary | Before | After |
|---|---|---|
| timeout | surface abandoned | released |
| interrupted | surface abandoned **and** no state persisted | released; `mechanism-failure` persisted |
| normal exit | resume reported `passed` over a stale surface, unreported | no leak to inherit |
| interrupt inside `start` | surface bound then abandoned (found in review) | released |

All three are exposures of one missing release obligation, not three defects. Relevant to RT05: a genuinely distinct boundary must lie outside this driver/runner ownership.

## Repair

- `_StartedOperations` — a proxy that records `(owner_id, operation_id)` for every operation this run starts. Chosen over a store-wide sweep so the ledger **can only ever name a surface this run opened**: exact ownership is proven by construction rather than by a filter.
- `_release_started` — best-effort release in reverse start order with a fresh bounded budget, re-raising the original error unchanged so classification stays coordinator-owned.
- `execute_release` now catches `BaseException`, keeping an interrupted cell explicitly resumable.
- Ownership is recorded from an `on_surface_opened` wrapper, i.e. at surface **bind** time rather than after `start` returns, closing the window where an interrupt during `start` left a bound surface owned by nobody. Any caller-supplied callback is preserved and still invoked, which the review lanes depend on.

Two boundaries were deliberately **preserved, not fixed**:

1. An operation already in `attention-required` is fail-closed — reported, never auto-closed, because releasing it destroys the evidence it exists to preserve. My first attempt broke the existing check `cleanup recovery preserves unrelated attention reasons`; the existing suite was right and I changed the fix to respect it.
2. When release cannot complete, the surface is named with the exact `harness-cli.py reconcile` recovery command. A silent leak became a visible, recoverable one; no in-process handler can cover `SIGKILL`.

## Regressions

`tests/test_live_acceptance_surface_cleanup.py` (new, wired into `make test` via `test-live-acceptance-runner`) drives production `run_cell`/`execute_release` against a double that models exact surface ownership. Committed red (4 failing), now green (13/13), deterministic over three runs. It records every boundary instead of failing fast so one repaired boundary cannot mask another. Paired negative guards assert the coordinator origin surface and an unrelated task's surface are never closed, and that closed ⊆ opened.

A test bug was caught and fixed mid-phase: per-manager surface ids collided across runs, so the resuming run reused a stale id and the normal-exit check passed spuriously.

## Parked findings (deferred deliberately — carry forward)

Review confirmed the deferral rationale was sound but required these to be filed durably rather than left in unstaged `.task-pipeline` transport. Filing them here, because the reap transaction turns this summary into the durable wiki result page; I did not write to `wiki/` directly, since vault mutations must go through `vault-write.py` and belong to the coordinator's single reap transaction.

**PARKED-1 — detection half of the repair (public-interface/schema boundary).**
The repair is prevention-only. After a `SIGKILL`-class termination, where no in-process handler can run, a later normally-exiting resume run still returns `status: passed` with a stale surface open and unreported, because the `schema_version` 3 report carries no surface-ownership field. Two pieces are deferred: an owner-scoped reconcile sweep on normal exit, and a report-schema surface-ownership field. The committed regression `a normally exiting run never reports success over a stale surface` passes through prevention, not detection — stated plainly so nobody reads it as detection coverage.
*Overlap to honour:* this same detection seam is implied by **RT05** (auto-close-miss trace) and **RT07** (read-only stale worktree/operation diagnostic). It should land **once**, in the existing doctor/preflight seam, not three times. Whoever takes RT05/RT07 should own it rather than RT02 reopening it.
*Why parked:* widening the report schema is a public-interface change; the plan routes such findings to typed parked findings rather than unilateral edits.

**PARKED-2 — classification vocabulary collision.**
An operator interrupt is persisted as `mechanism-failure`, because the state/resume vocabulary is pinned to `{runtime-contract, mechanism-failure}` (asserted by `tests/test_release_acceptance.py` and `scripts/release-acceptance.py`). But `AGENTS.md` states user cancellation is *not* by itself a mechanism failure, so a coordinator reading `live-state.json` after an interrupt could misread an operator action as a repairable mechanism defect. The bucket is used solely to keep the cell explicitly resumable; it is not a claim that a mechanism failed. Resolve together with PARKED-1: either add an explicit `interrupted` value, or document the mapping where the vocabulary is defined.

**PARKED-3 — untidy interrupt exit.**
`main` still lets `KeyboardInterrupt` surface as a traceback. State is now persisted correctly, but the exit is not clean. Not covered by any proven boundary, so deliberately untouched.

## Review resolution

All three typed findings resolved; final HEAD `46f9738`.

- **`start-window-surface-leak`** (important) — **applied**. A real bug in my own fix, correctly diagnosed: the ledger recorded an operation only *after* `start` returned, but the surface is bound and `on_surface_opened` notified well before that, and an interrupt in the interval escapes `start`'s own `except Exception`. The reviewer also correctly identified why my regression missed it — the double never invoked `on_surface_opened`. I reproduced the leak as a failing check first, then fixed it by recording at bind time. The double now notifies the seam like production does. A narrower window remains inside `supervisor.effect`, between cmux returning a surface and the store persisting the binding; that belongs to the write-ahead effect machinery and is recovered through its pending-effect reconcile path, not here.
- **`spec-001-deferred-detection-gap-needs-durable-parking`** (minor) — **applied** as PARKED-1 above, including the RT05/RT07 overlap note so the detection seam lands once.
- **`spec-002-interrupt-bucketed-as-mechanism-failure`** (minor) — **applied** as PARKED-2 above, recorded with the schema decision as requested.

I did not escalate: findings 1 and 2 are minor, the reviewer affirmed the deferral rationale, and the requested action was durable filing rather than a decision I needed to hand back. Raising would have paused the task for something the review itself called sound.
