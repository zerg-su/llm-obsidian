# 2.5 real dogfood RT04 invalid review callbacks

## RT04 — four invalid review callbacks: classified, one cause class repaired

Final HEAD `300250e305a2ad9325668ddd661164e32f3907f1`. Three commits: `d670419` (regression coverage), `0c2566f` (minimal fix),
`300250e` (all five review findings resolved).

### Forensic classification (durable content-free evidence only)

The four callbacks live in exactly one channel: `.vault-meta/pipeline-events.jsonl`, as `op=review-round`
events whose `counts.invalid_callbacks` sum to exactly 4 (vs 115 valid). Nothing in `wiki/`, `docs/`,
`.vault-meta/harness/**`, dispatch state, or 57 sibling worktrees records them — the count is derivable
only by aggregating that counter.

Recovering each round's phase start from `ts - duration_ms` splits them **2 incidents, not 4**:

- **Incident A** — session `019f4818…`, `opus:light`, iteration 1. Two phase starts agree to **55 us**,
  events **72 ms** apart, ~2.9 s of review time. One round, payload delivered twice; too fast to be
  reviewer output. Duplicate-delivery artifact.
- **Incident B** — session `019f6ddd…`, `fable:full`, iteration 2. Phase starts **5 h 11 m** apart,
  review times **5 m 45 s** and **51 m 28 s**. Two independent real review rounds rejected by the same
  versioned contract — the repeated transport-invalid signal `docs/pipeline-observability.md` calls a
  mechanism failure.

All four came from one emitter: `cmd_receive` in the legacy `spawn_review.py`, firing only inside
`except ReviewContractError`. `04cb7ed` deleted that file, so **the historic transport no longer exists
and those four are not reproducible as-is**. Two repository-owned causes on the successor mechanism were
reproduced deterministically instead, and both are repaired.

### C2 — reviewer could not know the contract

`review_submit._round_result` validates by exact field-set equality but kept its field sets as
unexported locals, so every prompt restated them as prose and the harness gate prompt in
`task-review-runner.py` named **none**. Fix: `ROUND_FIELDS`/`FINDING_FIELDS` promoted to module
constants, validator derived from them, and both reviewer prompts rendered through
`round_schema_lines()`. Review then showed keys were only half the contract, so the renderer now also
states the enforced `verdict` and `severity` vocabularies (derived from `review_contract.VERDICTS`
/`SEVERITIES`, not restated), the `line` and `schema_version` rules, and the approve/material-finding
rule. Validation strictness itself is unchanged — it was deliberate; the defect was that it was
uncommunicated.

### C1 — documented evidence channel had no producer

`docs/pipeline-observability.md` documents "Valid / invalid callbacks" and `pipeline-stats.py` still
consumes both counters, but the only producer died with `spawn_review.py`. Every current-runtime
rejection incremented nothing, so the report read `Invalid review callbacks | 0` while real rejections
occurred — the direct blocker of RT04's own method. Fix: emit at the surviving per-lane `_envelope`
seam, content-free (counters, route, iteration only), non-fatal, re-raising the original error so
fail-closed control flow is byte-for-byte unchanged.

Review found two real defects in that emitter, both fixed:

- Callback files are re-read on every coordinator poll and never consumed, so the counter fired **per
  poll, not per round** — deep-mode polling re-counted the same valid round, and a poll during
  `verifying` read the previous iteration's callback and blamed the reviewer for it. Now at most one
  event per (round identity, outcome), via a marker written only after a successful emit; and a
  round/iteration mismatch raises `StaleRoundCallbackError` and is never counted as invalid, so the
  schema-valid rate keeps meaning "rejected by the JSON contract".
- `vault_root` was not passed, so `origin_vault()` returned `None` for a **current-checkout** review
  (no worktree metadata) and its rejections stayed as invisible as before. Now explicit.

Actor's fourth segment is review depth, now documented: vocabulary is `simple`/`deep` where pre-2.3
rows carry `light`/`full`, so the two generations are not comparable on that segment.

### Why the regression escaped

`tests/test_pipeline_events.py` writes `"valid_callbacks": 1` into its own synthetic sample, then
asserts a 100 percent rate. Consumer-only coverage fed by the test itself — it passes with zero
producers, which is why `04cb7ed` broke a documented contract without turning CI red.
`tests/test_review_callback_evidence.py` (`make test-review-callback-evidence`, **28 checks**)
deliberately avoids that shape: it asserts the producer/consumer/doc triangle against the tree,
exercises the report at a non-zero invalid count, round-trips the **real** generated prompt through the
**real** submitter for every advertised verdict/severity pair, and covers the current-checkout and
idempotence lanes. It imports the field sets from the module that enforces them, so the assertion cannot
rot. During this work that producer check caught a regression I introduced myself (an f-string counter
key erased the literal names).

### Review findings

All five typed findings resolved as **applied** in `300250e`; none was rejected and none required
escalation (two `important`, three `minor`; no `blocking`). Finding rt04-holistic-4 was applied via its
own second option — documented residual rather than code — see below.

### Parked findings — deliberately not fixed

1. **Worker-path rejections remain invisible.** The fix instruments the review-gate seam, not
   `runtime_worker`/`CallbackBroker`. Not mechanical: `scripts/harness/**` has no telemetry imports, and
   on several rejection paths the envelope is unparseable so `kind` is unknown — emitting `review-round`
   for a `result`/`wiki-summary`/`research` callback would corrupt the metric. Needs an event-shape
   decision. This is the residual with live behavioural consequence.
2. **Sibling counters still orphaned.** `rounds_started`, the findings-severity counters and the
   review-round duration lost their producer in the same port, so the report block can show non-zero
   valid callbacks beside zero rounds started and zero findings. Now documented in
   `docs/pipeline-observability.md` as missing instrumentation rather than a clean window. Restoring the
   findings counters additionally needs a vocabulary decision: `critical/important/minor` is emitted
   while `blocking/warning/nit` is reported. Inventing that mapping was out of scope.
3. **Undifferentiated rejection artifacts.** `runtime_worker.py` writes one `callback-invalid` status
   for ~12 distinct causes, with no reason code, `callback_id`, or timestamp.
4. **No per-lane containment.** One invalid callback still aborts the whole gate poll. Swallowing it
   would make a rejection indistinguishable from "no callback yet", so the gate would hang rather than
   surface the fault — a behavioural change with a masking risk.
